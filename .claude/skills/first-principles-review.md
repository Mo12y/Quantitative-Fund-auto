> **v2.10 据首次实测修正 7 处**（2026-09-20，让一个全新上下文的执行者按 v2.9 真跑一次审计）：① 状态列与三判定**词汇互不兼容**——执行者被逼发明 `有问题（已确认）`，这是 v2.9 唯一的自相矛盾处，现已拆成「覆盖状态」+「判定」两列；② `审过` 与"留有悬念"的禁令过宽，改为允许「残留未知」但须写成具体事实；③ 降级出口**循环**（同会话做不到"禁读自己上轮原文"），改为"开不出新上下文就降级结论"；④ 预算差额（17.4 留 1 次 vs 18.3 要第二个确认者）；⑤ "按行名排序"是**仪式**（中文无 collation），改按指纹排序；⑥ 台账缺三列（枚举依据 / 已知-新增 / 残留未知）；⑦ `【口径】`的示例路径是**死链**（SSOT 在 `docs/00-规范/`）。

## 一、选题框架：痛点优先

**正确路径**：痛点是什么 → 谁会需要 → 为什么会发生 → 怎么解决 → 数据哪来 → 是预测未来吗 → 成本可控吗

**每一步要回答什么**（含常见错误）：痛点是什么（谁痛苦、多痛，具体到人群和损失，不是"有数据可分析"）｜为什么会发生（系统性还是个例，别跳过直接给方案）｜怎么解决（系统输出什么、帮到谁，不是"做聚类分析"）｜数据哪来（具体 URL/翻页/反爬难度，不是"网上有数据"）｜预测未来吗（X 在时序上先于 Y 吗、标签天然还是构造，避免事后诸葛亮）｜成本可控吗（三本学生 10 周做得完吗，别假设每天 8 小时高效）。

**错误路径（禁止）**：找数据源 → 想能做什么分析 → 包装成问题。变体：看到别人的项目/方法 → 想"做个类似的" → 反推痛点（方法启发式选题，同病根）。

**痛点真实性三问**：
1. 有真实的人会为解决方案付钱吗？
2. 影响多少人、每人损失多少？（要具体，不说"很多人"）
3. 为什么现在没人解决？（数据拿不到→你也拿不到；没人用数据方法做过→你有机会）

## 二、审查四步法：钢人化 → 第一性原理 → 对抗式审查 → 奥卡姆剃刀

### 第 0 步：钢人化（Steelman）—— 先构造最强版本
> 2026-09-16 新增（规则 16）。对抗式审查是 **strawman 方向**（专找破绽），直接开火容易"打倒了弱版本就以为驳倒了整个想法"。**审查之前先做这一步**：
1. 列出**没说出口但默认成立**的假设，并标出**哪一条一旦不成立、方案就塌**
2. 指出**缺哪条关键信息**，以及它取不同值时结论会怎么变（决定"先去找哪条信息"）
3. 点名这类问题的**最常犯的那一个**错误（只给一条）
4. **只问一个问题**，问完**等回答**，不要一边问一边给结论
> ⚠️ **触发条件**（对齐 `AGENTS.md §四-1`）：**只有**「前提错误会推翻方案」或「两条路径代价相差一个量级」时才走这一步；其余情况一行 `假设：…` 后直接做——**不许把钢人化变成分析瘫痪的挡箭牌**。

### 第一性原理
- **拆解**：物理/数学含义、输入输出、去掉它核心功能还能不能跑
- **因果链**：特征→标签方向对吗、有隐藏混杂变量吗、"相关性"被包装成"因果性"了吗
- **删除测试**：删掉还能回答核心问题吗？能=装饰品砍，不能=保留

### 对抗式审查（5 攻击）
1. **假设**：最核心假设不成立，方案会不会塌
2. **数据**：真能拿到吗（翻页深度实测）、有系统偏差吗、标签有时序泄露/循环论证吗
3. **替代**：更简单的方法/数据源能不能达到同样效果，跟标准做法有无本质区别
4. **规模**：真实可用时间内能做完吗、卡住有无降级路径、最低可交付版本是什么
5. **叙事**：一句话讲清解决什么问题、和同学区别、结果不好看论文还有无价值

### 奥卡姆剃刀
1. 两特征 r>0.8 → 留物理含义清晰的
2. 一个模块能被一条 SQL 替代 → 它不该是模块
3. 实验与核心假设无关 → 砍
4. 面板信息能从别处推导 → 砍
（V4 实证：37 特征→12、5 实验→2、7 面板→3、6 爬虫通道→2）

## 三、19 条审查规则（按主题分组）

### 选题层

#### 规则 3：换题不换逻辑
**来源**：VTuber IP 监测 = V1/V2/V4 换壳。
**核心**：新方向必须换数据源类型 + 换分析逻辑，否则只是换壳。
**触发**：提出一个"新"方向。
**三问**：① 数据源类型变了吗（不是换平台）② 分析逻辑变了吗（不是换因变量名）③ 旧方向被否的原因，新方向也成立吗？——全答"没本质区别"→ 放弃。

#### 规则 13：题目锚定检查
**来源**：市场池永远 91 样本时，"模式挖掘"空转——工作越做越多，没人问"这步兑现题目哪个词"。
**核心**：论文题目是承诺清单（如 Spark=分布式、互动节奏=行为层时序、模式挖掘=分布/聚类/对标）；工作会漂移，每加一步都要重新对齐。
**触发**：新增模块/功能/分析/页面；工作清单越拉越长；里程碑之间。
**三检查**：① 当前这步兑现了题目的哪个词（哪个都没兑现=漂移）② 有没有哪个词一直空转（如只做了描述统计却承诺"模式挖掘"→ 补齐或改题）③ 是让承诺"更实"还是让系统"更全"（更全≠更对，不服务承诺的砍）。
**区别**：规则 3 防换壳（方向↔方向）；规则 11 防结论过时；规则 13 防工作漂移（题目↔工作）。

### 数据层

#### 规则 1：数据源验证必须先于方案设计
**来源**：V4 花 2 周 debug 爬虫，天花板在服务端不在代码。
**核心**：数据源上限没确认之前，不投入方案设计。
**触发**：提出新方向或新数据源。
**动作**：第一天就跑翻页深度测试，确认是"翻到底了"还是"API 不给更多了"——三项：列表页翻页到返回空/报错（约 1 小时）、抽 10 条看关键字段完整性（约 10 分钟）、逐步加速请求测反爬阈值（约 1 小时）。

#### 规则 2：预测目标可观测性
**来源**：V2 想预测 VTuber"毕业"——但毕业是公司决策，数据里看不到。
**核心**：要预测的东西必须在数据里被记录，否则不可预测。
**触发**：定义一个预测目标。
**判据**：能预测（股价、航班延误、猪价、房子几天卖掉——数据里有）；不能预测（离职、断更动机、战略放弃、考试成绩——发生在数据之外）。

#### 规则 5：标签天然性
**来源**：V2"断更45天=流失"自定阈值、V4 双人标注从未执行。
**核心**：标签尽量天然存在；构造标签需文献支撑或敏感性分析。
**触发**：需要构造标签（而非使用天然标签）。
**三问**：① 标签天然存在吗（最安全）② 构造规则有学术文献吗（有→可；自定→需敏感性分析）③ 需人工标注但只有你一个人吗（→高风险）。全指向高风险 → 换方向或改方法。

### 方法层

#### 规则 8：方法选择由样本量决定
**来源**：V1 用 40 样本跑 RF/GBDT，严重过拟合；改相关性分析后才是方法论诚实。
**核心**：先数样本再选方法，别让 tech stack 驱动方法。
**触发**：选建模方法。
**判据**：几十~几百条→相关/线性回归/规则（RF/GBDT/LSTM 过拟合）；几千→逻辑回归/朴素贝叶斯+K-fold；几万+→RF/XGBoost 合理。简单模型结论也成立→用简单模型。
**论文写法**：样本少时——"受限于样本量，采用统计相关性分析；预测模型的训练需更多数据，留待未来工作"。

#### 规则 12：方法论选择用实测对比
**来源**：两次推理被实测打脸——"连续谱无结构"实测 K=2 silhouette 0.385（随机 0.15）；"GMM 预期 K=1~2"实测 BIC K=4。
**核心**：推理只能生成假设，实测才能生成结论。
**触发**：选 A/B、验证旧结论、判断可行性。
**两铁律**：① 方法对比同口径实测（同一数据/预处理/指标下跑）② 旧结论在新数据/新口径下必须重测。能跑就写 20 行脚本先跑，不能跑就明说"这是推断"。

### 地基 / 风险层

#### 规则 6："没被挑战过的东西"检查
**来源**：情感分析是跨学科招牌，挑战了一切唯独没挑战它。
**核心**：删除测试只对你愿意用的东西有效；承担叙事功能的模块免疫于删除测试。
**触发**：完成一轮删除测试后。
**检查**：① 什么从 V1 到 V4 从没被动过 ② 它承担了什么非技术功能（跨学科抓手/差异化锚点/好讲的故事）③ 移除它核心问题还能答吗。

#### 规则 7：地基验证——先验证最底层依赖
**来源**：V1 SnowNLP 准确率是地基，地基准了上面全歪。
**核心**：找到依赖链最底端（错了上面全是垃圾），先验证它。
**触发**：方案设计完、准备实施。
**三步**：画依赖链（结论←模型←特征←方法←数据）→ 找最脆弱环节 → 先验证它。
**地基不成立的退路**：SnowNLP 准确率不够→换 LLM few-shot + 轻量分类器；API 翻页有限→降级为纯元数据方案；季报缺失→缩小行业范围到数据完整的。
**区别规则 1**：规则 1 验证"数据拿不拿得到"；规则 7 验证"拿到后最基础的分析方法行不行"。

#### 规则 9：最没把握的事——先处理它
**来源**：弹幕方向看似就绪，追问发现截断、UP主需求都没验证。
**核心**：你最心虚的往往就是决定成败的变量。
**触发**：方向决策前、汇报前、写开题前。
**三问**：① 最虚的是什么（不行方案就塌的）② 为什么还没验证（难？怕坏结果？）③ 现在验证最坏结果是什么（现在报废好过开题后报废）。

#### 规则 10：最大遗漏——你在回避什么
**来源**：每次被问"还漏了什么"都发现一个故意不看的东西。
**核心**：你回避的正是最大风险。
**触发**：觉得"方案差不多"时。
**四问**：① 一直绕开什么话题 ② 评委觉得哪里最可疑 ③ 该问没问的人 ④ 领域有没有已存在的官方系统/国家标准（路线 H 教训：没查国标 GB/T 42072-2022）。

#### 规则 11：地基再验证——"已确认结论"会免疫于质疑
**来源**："连续谱"被测试数据确认后，敏感性/PCA/叙事全在叠楼；用正式数据重测才发现 K=2 有结构（0.385 vs 随机 0.15），旧结论是"只测 K=4-6、漏测 K=2"的方法盲区。
**核心**：结论确认后变成地基，投入越多越不敢质疑——路径依赖 + 沉没成本 + 确认偏误三重锁定。
**触发**：在"已确认结论"上持续叠加新工作（第 N 次叠加）。
**三检查**：① 当初用什么确认的（测试 vs 正式/口径/样本量），现在有没有新数据/新口径/新角度能重验 ② 地基错了哪些楼会塌，有没有一直没走的另一条路 ③ 最近是在"为结论找证据"还是"质疑结论"——全支持零质疑 = 已被锁定，主动安排一次地基再验证。
**区别规则 7**：规则 7 是新地基先验证；规则 11 是已确认地基定期重验。

### 过程层

#### 规则 4：完美主义的正确用法
**来源**：在天花板下修 3 个 bug，修得再好也没用。
**核心**：完美 = 所有问题都有解决方案，不是没有问题。
**触发**：反复打磨一个方案/模块。
**正确 vs 错误**：验证"有没有不可克服的硬伤"（一天出结果决定做不做）✅；优化"还能不能再好一点"（两周不改天花板）❌。
**终点**：剩余问题不致命且差异化已足够，就说"够了"——不必找第 N+1 个漏洞。

### 交付层

#### 规则 14：事实来源分级
**来源**：9/4 独立审查发现 3 处硬编码结论（`0.3852` / `~78%`）——数字没有出处，口径改了也没人发现；DSH 也把交接摘要里的数字（297,675 条弹幕 / sil 0.4448）当成本轮实测直接引用。
**核心**：陈述的可信度取决于**来源可查**，不取决于语气肯定。
**触发**：引用任何数字、人物、时间、结论。
**四级**：`【实测】`本轮跑过/查过，附命令或 `文件:行号`｜`【口径】`来自 `docs/00-规范/结论权威口径.md` 等权威文档，注明文档名，**不等于本轮验证过**｜`【文献】`附链接/出处｜`【推测】`写明依据 + 证伪条件。
**纠错格式**：发现用户判断有误时用「你说的 X → 我读到的 Y（依据…）→ 确信度 高/中/低 → X 成立需要什么条件」；禁止只表态、禁止明知有错顺着说；确信度低就说没把握，**不许为显得独立而制造分歧**。
**区别规则 1**：规则 1 验"数据源天花板"（方案能不能做）；规则 14 验"嘴里这个数字从哪来"（说得对不对）。

#### 规则 15：完成即验证
**来源**：① DSH 统一登录页按钮样式时，把页面**唯一**的 `addEventListener` 一起删掉，仍宣布"按钮已统一" → 用户实测"点了没反应" ② `pkill -f 'python web/app.py'` 连承载命令的 ssh 进程一起杀，两次表现为"命令莫名卡死"（第二次是在这个坑已写进文档之后） ③ Claude 侧改 Jinja 模板未重启 Flask，改动不生效。
**核心**：拿不出可检验证据的"完成"不算完成；工具反复异常时**先怀疑自己的用法**。
**触发**：准备说"已完成 / 已修复 / 已上线"之前。
**三检查**：① 成功标准是什么、**用什么命令或页面能看到它**（HTTP 码 / 文件 diff / 接口返回 / 截图）② 我删改的东西有没有**唯一依赖**（事件监听、加载路径、被别处引用的变量/函数）③ 失败或无响应时：先查自己（模式匹配到自身？缓存未刷？服务未重启？），再查环境。
**措辞纪律**：未验证就说"未验证"，并写明**没验证的是哪一部分**；不许用"应该没问题""理论上可以"结案。
**区别规则 12**：规则 12 说"能跑就先跑"（方法选择）；规则 15 说"跑完要留下能看的东西"（交付验收）。

#### 规则 16：钢人化前置——先构造最强版本，再开火

**来源**：2026-09-16，DSH 对照外部的 Steelman 提示词模板，发现本 skill 的审查是**单侧对抗**——「对抗式审查 5 攻击」、删除测试、「最致命一击」全是 strawman 方向（专找破绽）。而 `AGENTS.md §四-2` 早已写下「**不许为显得独立而制造分歧**」——那条护栏正是这个缺口的症状：打倒了方案的**弱版本**，就以为驳倒了整个想法。
**核心**：审查之前，先把对象的最强版本构造出来（补齐假设、标出缺失信息、排除常见错误）。否则你反驳的可能只是自己树起来的靶子。
**触发**：任何「做还是不做」「选 A 还是选 B」的决策；**尤其是你已经倾向于否定时**——确认偏误最容易在这里伪装成"独立判断"。
**四步（缺一不可）**：
1. **补全假设**：列出没说出来但默认成立的前提，标出**哪一条不成立方案就塌**（→ 接规则 7 地基验证）
2. **标出缺失信息**：缺哪条关键信息？它取不同值时结论会变成什么（"若是 A 则做、若是 B 则不做"）——这决定了**先去找哪条信息**（→ 接规则 4 / 规则 12）
3. **点名常见错误**：这类问题人们最常犯的**一个**错误是什么（只给一条，不许罗列）
4. **只问一个问题**：问完**等回答**，不要一边问一边给结论
**与相邻规则的区别**：规则 7 / 10 审查的是**自己**（地基 / 遗漏）；规则 16 是**先加固对象、再审查**，对象是别人的方案或用户的提问。规则 12 说"能跑就先跑"（用实测代替争论），规则 16 说"跑之前先把假设说全、把缺的信息点出来"。
**护栏（最重要的一条）**：本步**只在触发条件成立时**才走 —— 即「前提错误会推翻方案」或「两条路径代价相差一个量级」（对齐 `AGENTS.md §四-1`）。其余情况仍是一行 `假设：…` 后直接做。**不许把钢人化变成分析瘫痪的挡箭牌**——这也是它与外部模板最大的不同：外部模板默认"先问再答"，本项目默认"能动手就动手、不许空转"。

### 审计层（v2.9 新增）

> 这一层管的不是"方案对不对"，而是"**审计/复核这件事本身可不可信**"。触发于任何"我检查过了 / 已修复 / 已验证"的交付。

#### 规则 17：审计要记账覆盖面——清单先行，状态必填必空

**来源**：2026-09-18 复核 Claude 的「审计 v2 整改 P1/P2/P3」交付，查出 **9 项它没有上报的问题**（论文主文 7 处「62%±7% 主流模板」旧结论、`p3_absolute_time` 的 mainstream 定义假象、T_cap=1200 那一档被整体丢掉…），而它的交付报告写的是"已完成"。事后**无法回答"它到底查了哪些范围"**——因为整轮审计没有任何覆盖面记录。对照 Cloudflare 开源的 `security-audit-skill`：它用 `coverage-ledger.json` 把"查过什么"变成一等文件，并实测**单次审计大约只找到重复审计总量的一半**。
**核心**：**说不清覆盖面，就不能声称完成**；任何一次审计/复核都必须自称**局部覆盖**。"没查"不是罪，"**没查却算成没问题**"才是。
**触发**：交付任何审计 / 复核 / 自查结论之前；有人说"已经全面检查过了"。
**四条（缺一不可）**：
1. **清单先行**：开工前先列台账，每行 = `被审对象 :: 会出错的地方 :: 被审的假设`。行名**本轮内不许改名**、**跨轮复用同名**；清单**按指纹 ASCII 升序排**（可复现——中文行名没有 collation，按行名排是仪式）。同一个行名指向两件事、或同一件事出现两个行名 → **停下报告，不许静默合并**（防"两个问题合成一条显得干净"，也防"一条算两条显得干了活"）。
2. **必须记「枚举依据」——这是覆盖面真正的边界**：每行要写清**你是用哪条命令/哪组关键词把这一行圈进来的**。只记"查过哪些行"是不够的：**没有数字的措辞（如"唯一稳定出现的结构特征"）第一轮关键词往往扫不到，是第二、三轮才补上的**——若只做第一轮，台账照样显示 100% 闭合，而漏掉的永远不会出现在"未审"行里。**"清单先行"在文档审计里必然退化为"先枚举扫描 → 冻结行名 → 逐行判定"，这是允许的，但枚举依据必须留痕。**
3. **两套词不是一回事，别混用**：
   - **覆盖状态**（只描述"查没查"）：`待审`（不许夹带任何结论）／`审过`／`不适用`（必须写原因）／`未审`（必须写原因）。
   - **判定**（只描述"结论定了没"，只有 `审过` 才允许有）：`已确认`／`待查证`／`已否证`；`待审`/`不适用`/`未审` 行的判定列必须是 `—`。
   - `审过` 必须逐条给出**实际看过的 `文件:行号`**（概括性描述不算，该行的位置集合**只能由这些条目拼出**）。
   - ⚠️ **v2.10 修正**：v2.9 把"有问题"当成状态、又要求"审过与留有悬念不能同时成立"，导致"查实了、与权威口径冲突"这种最常见的行**填不出来**（实测：执行者被逼发明 `有问题（已确认）`）。现改为：**"有问题" = `审过` + `已确认`**；`审过` 行**允许**有「残留未知」（真实世界最常见），但不许用它掩盖没查——判据是「残留未知」**必须能写成一条具体事实**，写不出来就是没查。
4. **显式排除**：**考虑过但不审**的对象必须单独成行写"不适用 + 为什么"，且不得与在审行同名。没进清单的东西最容易变成"看起来 100% 覆盖"。
5. **预算先算后开工**：先把本轮**必须保留**的独立复核额度扣掉——**常规 1 次；若预判会出现"加强结论"（`待查证 → 已确认`）则要 2 次**（规则 18.3 要求加强必须由**第二个**不知情者确认），再留 1 次补漏；只拿剩下的去审。**扣不出来就整轮不审**，直接记"未审 + 原因"。额度只够一部分时按指纹顺序审，其余全标 `未审` 并写原因。结论**第一行**必须写「已闭合 X / 共 Y 行」并声明闭合口径（哪些状态算闭合），列出未审行；覆盖不满时第一行必须标注「**本轮覆盖不完整**」。**禁止**为凑覆盖率把 `待查证` 改写成 `已确认`，也**禁止**用"没时间了"当"已覆盖"的证据。
**台账模板（直接抄）**：

```markdown
| 行名（对象::出错点::被审假设） | 覆盖状态 | 判定 | 影响 | 位置证据（文件:行号，逐条） | 枚举依据（哪条命令/关键词） | 指纹 | 已知/新增 | 残留未知 |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|
| SSOT::峰值中位口径::以为只有一个口径 | 审过 | 已确认 | 低 | `结论权威口径.md:95`；`g02_stability.py:41` | `grep -n "峰值中位\|46.7"` | peak_median.caliber | 已知（上轮已登记） | 历史 486 条口径的原始来源不可追溯 |
| p3_absolute_time::主流占比定义::以为占比可跨脚本比较 | 审过 | 已确认 | 中 | `scripts/p3_absolute_time.py:115` | 通读脚本 + `grep -n mainstream_ratio` | mainstream_ratio.definition | 新增 | — |
| data/archive::旧批次快照::以为可以清掉 | 不适用 | — | — | — | 清点报告 P2 条目 | — | 已知 | — | 含"9/02 批真实榜单日=8/12"的证据，删则毁证据链 |
```

> **三个只有本模板才有的字段，别省**：`枚举依据`（覆盖面的真实边界）、`已知/新增`（没有它就无法表达"这是重发现"，规则 19 的指纹复用条款也就无从执行）、`残留未知`（"已确认 + 还有不知道的"是最常见的真实形态，藏起来就等于说谎）。

**与相邻规则的区别**：规则 15 管"这一次动作有没有留下证据"（点）；规则 17 管"这一轮审计覆盖了哪些范围"（面）。规则 11 管"已确认结论要不要重验"（时间）；规则 17 管"这轮到底查了哪些格"（空间）。
**护栏**：台账是**给人看的地图**，不是仪式——超过 30 行按模块合并，粒度以"一行能不能独立判对错"为准。

#### 规则 18：发现者不得自己结案

**来源**：本项目长期是"做的人自证"——Claude 交完 P1/P2/P3 自己写 SESSION_LOG 说完成；`p3_absolute_time` 那处 mainstream 定义假象能一路留下来，正因为**结论由发现者自己写、没人被要求去证伪它**。Cloudflare 的设计原则原话：**"The agent that checks a finding is never the agent that found it"**，且其查证者提示词开场即 "You did not write this candidate. **Try to refute it**"。
**核心**：给结论盖章的必须是**另一次运行 / 另一个智能体**；同一轮上下文里的自我复核**不算**独立验证。
**触发**：要把任何结论写成"已验证 / 已修复 / 已完成"之前。
**三条**：
1. **复核者先自己看、先自己写**：先重读被引用的位置、独立写自己的结论，**然后**才看原结论的文字；只回答三问——**位置对不对 / 有没有反向证据 / 影响是否被夸大**。（Cloudflare 的对应要求是"重建这条路径上最强的验证/鉴权/归一化/生命周期控制"，即主动去找"为什么这个结论是错的"，而不是确认它对了。）
2. **复核者不得看到其他复核者的结论**——防"几个查证者互相抄 → 共识即正确"。
3. **加强结论的修改必须换人**：任何把结论**加强**的改动（尤其 `待查证 → 已确认`）必须由**第二个不知情者**再确认一次；**拿不到就撤下该结论、记为未解**，并说明本轮不完整。
**降级出口（v2.10 重写——v2.9 那版是循环的）**：换人 = **必须新开一个上下文**（子代理 / 新会话）。同会话里"换一轮冷读 + 禁读自己上一轮原文"**物理上不成立**——上下文里已经有了，做不到"禁读"（2026-09-20 实测：执行者明确报告这条出口是循环的）。所以改为：**开不出新上下文时，把结论降级**——不许写 `已确认`（只能写 `待查证`），并在结论第一行注明「本轮无独立复核，结论未升级」。**这把"环境不允许"从一个可以绕过的出口变成了一次可测量的降级。**
**与相邻规则的区别**：规则 12 要求"实测"（别用嘴论证）；规则 18 要求"**实测的人不是下结论的人**"。规则 16 是"开火前先加固对象"；规则 18 是"结案前换个人来开火"。

#### 规则 19：每条线索必须落成三种判定之一

**来源**：本项目大量"说不清但确实存在"的线索被混进正文——`T_cap=1200` 的相邻批显著维度 3 个（基线 0）在报告里被**直接省略**；审计 v2 三项"塌陷半径"验证有真有假难分。Cloudflare 在 schema 里把 `needs_validation` 的 `severity` 字段**物理删除**（`additionalProperties: false` → 出现即结构错误），脚本层再拦一道：**"待查证"在结构上不可能冒充"已确认"**。
**核心**：三种判定**字段互不通用**，每条线索必须落成其中一种：
- **已确认**：位置（`文件:行号`）+ 可复现证据 + 影响 + 成立条件；且**影响等级不得高于已证实的影响**（"证据弱、语气强"= 违规）。
- **待查证**：位置 + 证据 + **卡住它的那一条具体事实** + 至少一条不依赖生产的查证动作；**不许写修复方案、不许写成"低置信度的已确认"**。
  - ⚠️ **"影响/严重度"只在 `已确认` 写**：`影响` 指的是**已经证实的后果**（写在已确认行）；`高/中/低/严重` 这类**等级词只是它的标签**。`待查证` 行里出现任何等级词即违规——因为它证实的后果为零。已确认行也必须满足「**影响等级不得高于已证实的影响**」。
- **已确认但有残留未知**（最常见的真实形态）：判定写 `已确认`，同时在台账的「残留未知」列写**一条具体事实**。这不是"留有悬念"，是**如实标注已知的边界**。
- **已否证**：位置 + 证据 + 否证理由；**留在清单里**，下一轮不带新证据不许重提（否则下一轮会把同一件事重跑一遍）。
**指纹**：每条线索一个指纹 = 「被审对象 + 出错部位」的短串，**不含轮次 / 日期 / 严重度 / 判定结论**；**同一根因跨轮必须复用同一指纹**（防"同一个问题换个说法就是新发现"）。历史结论进入新一轮时**只允许带三样：指纹 + 一句话标题 + 根因**——证据、复现步骤、叙述全部剥掉，**不许当"范例"**（用上一轮的结论给这一轮定框 = 锚定）。
**触发**：写审计结论、写论文的"不确定"段落、把线索交接给别人时。
**检查**：① 每条"待查证"有没有写出**具体缺什么**（"还需进一步验证"= 没写）② 有没有给它标了严重度或风险等级（= 违规）③ 被否证的候选有没有留档 ④ **报告的文字不得改判**——报告写得比记录好看 = 违规，两者不一致**以记录为准**。
**与相邻规则的区别**：规则 14 管"这句话的来源等级"（可信度）；规则 19 管"这个结论到底定没定"（状态）。规则 11 说"已确认结论要定期重验"（时间维度）；规则 19 的降维进场说"历史结论不许给新一轮定框"（信息维度）。
