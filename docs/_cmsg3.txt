fix(前端/验收): 阶段 1 浏览器验收 —— 修曲线负号被裁 + favicon 404

补上计划书 §8 要求但从未执行的浏览器侧验收。过程中发现并修掉两个真缺陷。

== 缺陷 1：组合收益曲线的 Y 轴负号被裁掉（会误导读数）==

CurveChart.tsx 的 LineChart margin.left = -16，而 Recharts 的 Y 轴刻度是**右对齐**的：
"-4.0%" 比 "4.0%" 多占一格，-16 的负边距正好把多出来的首字符吃掉。
结果图上 **-4% 与 +4% 长得一模一样** —— 金融图里这是实质性误导，不是审美问题。

定位过程：DOM 里文本确实是 "-4.0%"（observe 可见），但截图上看不到负号，
一度怀疑是字形/缩放问题；读源码后确认是布局裁切，改为 margin.left: 0。
复验：修复后 y 轴清楚显示 4.0% / 2.0% / 0.0% / -2.0% / -4.0%。

== 缺陷 2：控制台 favicon 404 ==

两套前端（dashboard.html 与 frontend/index.html）都未声明 favicon，
浏览器回落到 /favicon.ico → 控制台一条应用级 404。而这正是计划书 §8
"console 无 error" 的验收项。
修：新增 src/web/static/favicon.svg（取色与新前端 token 同源，刻意不用涨跌色
—— 图标是品牌标识，不该随行情语义变色），两个 HTML 各加一行 link。
复验：网络层 /static/favicon.svg 200，且新加载不再请求 /favicon.ico。

== 过程中的两次自我更正（记下来免得下轮重踩）==

1. 首张截图曲线是空的、按钮显示"计算中…" —— 那是**预热态**，不是 bug；
   等预热完成后曲线满宽正常。Recharts 的入场动画还会让线只画到 ~7%，
   截到中间帧会误判成"渲染缺陷"。**取证前先等 idle。**
2. 我一度断言"五格没渲染" —— 实际是首次 observe 用了 maxTokens:4000 被截断。
   **obsorve 有 token 上限，长页面要分段看。**

== 环境（供下一轮复用）==

bsk 浏览器工具此前报 "unrecognized subcommand 'request'"：CLI 是 0.3.0 而插件 0.3.2。
实际是 CLI 自更新已完成替换、新版二进制刚生效；重启后 --version 即为 0.3.2。

须用 `bsk daemon start --foreground` 跑在持久后台任务里（本轮即如此）。
