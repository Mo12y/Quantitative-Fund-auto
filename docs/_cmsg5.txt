feat(调仓): 目标权益可覆盖 + 差额金额（与百分比同基数）+ 修旧前端基数错误

用户决策落地：目标金额要可调节（预期会变）、要给「还差多少」、结构分布单独成卡。
实现过程中查出旧前端的金额**算错了**。

== 一、查出的旧缺陷：同屏两个数用了不同基数 ==

rebalance_advisor.py:83  『total_capital = portfolio_value + cash_reserve』
                        （本机实测 = 854.51 + 280.0 = ¥1134.51）
rebalance_advisor.py:105 『current_equity_pct = equity_mv / total_capital * 100』
→ **33.9% / 36.9% 的基数是 ¥1134.51**

而旧前端 app.js:650
  `const base = P.has_holdings ? (P.total_invested||0) : (PL.total_capital||0)`
  `权益 ≈ base*eq/100`
→ 用的是 portfolio.total_invested = ¥852.89

于是同一张卡上：
  显示「36.9% 权益」，同时显示「权益 ≈ ¥314.72」
  而按 36.9% 自己的基数应是 1134.51 × 36.9% = **¥418.63**
  **差 ¥103.92（25%）** —— 用户照着做会少配 ¥104。

属本项目反复栽过的「同屏两个数互相打架」（F-03 同类），且这次是**同一张卡内**
两个数不自洽，比 F-03 那种跨卡更隐蔽。

修法：把基数与差额全部由后端给出，前端**不再自己乘**。

== 二、后端 ==

· rebalance_advisor.analyze() 新增 target_equity_override 参数
  （来自 config/user_profile.local.yaml 的 target_equity_pct，用户可覆盖温度模型）
  并在返回里加 target_source（'temperature' / 'user_profile'）——
  前端必须能说出这个数是谁定的，否则用户看到与温度不符的目标会以为模型算错。
· 新增 gap_amount 与 rebalance_pp(±5.0pp)；把 total_capital / portfolio_value 暴露出来。
· _all_rebalance 的返回**原先过滤掉了 total_capital**，前端根本拿不到基数
  —— 这是它能算出 ¥314.72 的结构性原因之一。现已一并给出。
· ⚠️ 只在确有覆盖时才传 target_equity_override：无条件多传一个 None kwarg 会让
  按旧签名打桩 analyze 的地方抛 TypeError，被 _all_rebalance 的 except 吞成
  {"error": ...}，表现为 11 个看似无关的测试同时 KeyError。少传一个 None 即可避开。

自洽性（实测 scripts/verify_equity_gap.py）：
  gap_amount 34.04 == gap_pct 3.0% × total_capital 1134.51 ✅
  need_rebalance False == (|3.0| > 5.0) ✅
  过程中先写成未取整算 → gap_amount 34.57 而屏上三个数只能算出 34.04（差 0.53），
  属同一类"同屏对不上"，已改为用**已取整的 _gap_pct** 折算。

== 三、前端 KpiRow ==

权益格改为：当前 33.90%（主）／目标 36.9%（温度模型）／差额／基数 ¥1,134.51。
设计取舍（用户授权我定 needs_rebalance 联动）：
  · **不隐藏数字，而是改主次**：把「目标绝对值」当主数字会被读成"我该持有这么多"，
    而它只是配置基准；差额天然在无需调仓时接近 0，不诱导操作。
    隐藏则留信息真空（用户不知道偏了多少）。
  · 在容忍带内 → 显示「差 +3.0% · 在容忍带内（±5pp）」；超出 → 显示「待补 ¥X / 待减 ¥X」。
  · **基数必须同框声明** —— 只给百分比、让前端自己找基数，正是 ¥314.72 的成因。

== 四、已知边界（明确记录，不静默）==

温度数据完全缺失时（F-02 分支）**即使设了 target_equity_pct 也不生效**，仍返回

走 _build_increase_instructions(..., temp, ...)，温度缺失下那条路径未经验证。
