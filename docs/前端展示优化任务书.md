# 前端展示优化任务书

> 一句话目标：**在不动任何业务逻辑、不破坏任何接口的前提下，重构前端卡片的展示逻辑、
> 提升阅读性，并在必要时重做图表的呈现方式。** 纯展示层改动，接口契约、数据口径、
> 账本、评分逻辑一律不得改。

---

## 0. 先读，再动手（工作方式铁律）

1. **先查成熟实现，再自己写。** 打开 `DESIGN.md`（本项目视觉 SSOT，已从 Linear 设计系统 +
   awesome-design-md 提炼），并**上网看 2~3 个成熟仪表盘的数据展示手法**再动手：
   - Vercel 的 Geist / analytics dashboard（信息密度、等宽数字、图表克制）
   - Linear（卡片层级、hairline 描边代替阴影）
   - shadcn/ui 的 card/table/chart 组件（可复用的展示组件形态）
   目标是"借鉴成熟做法"，不是凭空设计。
2. **先审计 → 定向修复，不推翻重写。** 本项目前端是纯 vanilla JS（无构建链、无框架），
   现有代码是能跑的，重构要**逐步、可回滚**，不要一次性重写 1129 行。
3. 每改一步跑一次 `python -m pytest tests/ -q`（当前基线 **390 passed**），并实际起
   `QFA_MARKET_LIVE=0 python src/main.py web` 用浏览器看一眼再继续。

- `src/web/static/app.css`（234 行）
- `src/web/templates/dashboard.html`（41 行）

**禁止项（任何一条都不能破）**：

- ❌ 引入任何框架/构建链/依赖（不装 React/Vue/Tailwind；不跑 npm；保持 vanilla JS + 单文件 CSS）。
- ❌ 删掉或改名任何已暴露的 DOM 结构（`#app`、`.main`、`.sidebar`、`data-view`、`#pool-card`
  等）—— 后端无依赖，但**既有的 agent-browser 黑箱审计 / 截图脚本靠这些选择器**。
- ❌ 违反 `DESIGN.md` 的硬约束：禁 emoji 当图标、禁渐变/霓虹/玻璃拟态、禁重阴影、
  大容器禁胶囊圆角、禁纯黑 `#000000`、禁廉价元标签（"SECTION 01" 之类）、文案直白。
- ❌ 为"好看"新增功能或新卡片（本项目铁律：不为了好看而加东西）。只**重排、去重、提可读**。

## 2. 现状与痛点（实测数据，照着修）

| 痛点 | 证据 | 为什么是问题 |
|---|---|---|
| **双渲染路径** | `renderApp()` @337 行（全量视图）与 `overviewViewHTML()` @1081 行（快速首屏）并存，总览卡片 HTML 逻辑写了两遍 | 改一处漏一处，两套总览会漂移（历史已踩过） |
| **内联样式泛滥** | `app.js` 里内联 `style="` 出现 **109 处** | 颜色/间距散落在 JS，绕过 DESIGN.md 的 token，无法统一维护 |
| **硬编码颜色** | 非 `var(--*)` 的裸色值 **24 处** | 违反"颜色一律从 token 取"铁律 |
| **内联事件** | 内联 `onclick=` **20 处** | 事件与结构耦合，难读难维护，应改为事件委托 |
| **卡片拼接逻辑分散** | `card()`/`seg()`/`poolRow()`/`boardPoolHTML()`/`overviewKpis()` 各写各的 | 卡片/行/徽标的渲染没有统一抽象 |
| **图表手写且不一致** | sparkline、组合曲线、行业占比条、温度仪表全是散落的手写 SVG/div | 无统一图表组件，样式/交互不一致 |

## 3. 重构要求（按优先级）

### 3.1 统一卡片渲染，消除双路径（最高优先）
- 让"快速首屏"与"完整视图"**共用同一套总览卡片渲染函数**（理想：快速首屏 = 同一函数 +
  数据未就绪时的占位/骨架），消除 `overviewViewHTML` 与 `renderApp` 里总览部分的重复。
- 收敛一套卡片抽象：`card(title, sub, inner, cls)` 与 `seg(head)` 已经是雏形，评估是否补
  `metric(label, value, sub)`（KPI 单元格）、`row(cells)`（列表行）等**最小**原语，让
  各视图（总览/持仓/筛选池/板块/量化）都走同一套，而不是各写各的 `<div>`。

### 3.2 消除内联样式与硬编码色
- 109 处内联 `style=` → 收进 `app.css` 的语义类（`.kpi`、`.pill`、`.bar`、`.poschip` 等）。
- 24 处裸色值 → 一律 `var(--*)`（DESIGN.md 已有 `--up/--down/--warn/--primary/--ink-*`）。
- 20 处内联 `onclick=` → 侧栏/卡片/按钮统一改成**事件委托**（在 `main` 或 `#app` 上监听
  `data-action`），保持 `showPool('type'|'board')`、`boot()`、`retryBtn` 等现有行为不变。

### 3.3 提升阅读性（这是"用户阅读性"的落地）
- **结论在前，明细折叠**：每个区块标题下一行直接给结论数字，细节进 `<details>`（项目已
  有先例：`历史回测验证` 折叠块）。总览页当前"口径说明"是长段落，评估是否折叠。
- **数字等宽 + 右对齐**：金额/百分比/净值统一 `font-variant-numeric: tabular-nums`，KPI 数值右对齐。
- **一屏信息密度克制**：一个区域 3~5 张卡，网格不留空单元格；同类信息排齐。
- **三态空态**：每个数据区块保留"加载中 / 有数据 / 空或异常"三态（项目 `DESIGN.md §6` 已有要求，
  但部分卡片缺失，需补齐）。
- **标签文案直白**：不写"赋能/一站式"，错误态用"加载失败 · 原因 + 重试"，不要只写"error"。

### 3.4 图表呈现（必要时才重做，不做也行）
- 现状是手写 SVG/div 的：sparkline（迷你走势）、组合累计曲线、行业占比横条、温度/仓位仪表。
- 允许做的：把它们抽成**一个统一的轻量图表原语**（如 `sparkline(series, color)` 已有，扩展为
  `lineChart`/`barRow`），统一配色（主线用 `--primary` 或语义色，网格 `#20242e`）、统一 tooltip 措辞。
- **禁止**：不引入 ECharts/Chart.js 等库（铁律：无新依赖）；不改任何图表背后的数据计算；
  不为了炫技把简单条改成复杂图。
- 温度仪表、仓位建议这类"结论型"展示，优先用**数字 + 短条**而非华丽仪表盘（DESIGN.md 已明确
  单一色相强调、图表不做装饰）。

## 4. 验收标准（全部满足才算完成）

1. **功能不回归**：`python -m pytest tests/ -q` 仍 **390 passed**（本项目前端无单测，主要靠
   下面这条人工+脚本验证）。
2. **接口/选择器不回归**：起 `QFA_MARKET_LIVE=0 python src/main.py web`，用浏览器（或
   agent-browser）走一遍 5 个视图（总览/持仓/筛选池/板块/量化），确认：
   - 每个视图能渲染、无 JS console 报错；
   - `#app`、`.sidebar [data-view]`、`#pool-card`、`#nav-pool` 等选择器仍在；
   - 筛选池"按类型 / 按板块总榜"切换、`历史回测验证`折叠块仍可用；
   - 冷启动 `status=warming` 时前端仍能显示"正在准备数据"并自动重试（不回归）。
3. **可读性达标**：截图对比重构前后，评审维度 = ① 结论是否前置 ② 数字是否等宽对齐
   ③ 是否还有内联样式/裸色（理想归零或仅剩不可避免的极少数）④ 空态是否三态齐全。
4. **代码度量改善**：`app.js` 内联 `style=` 从 109 处 → **≤ 20 处**；裸色值 24 处 → **0**；
   内联 `onclick=` 20 处 → **0**（用事件委托）。
5. **无新增依赖**：`git diff` 里不出现 package.json / node_modules / 任何 CDN `<script>`。

## 6. 排雷提醒（历史踩过的坑）

- `boot()` 是**两阶段**：先轻量总览再 `/api/all` 补全；冷启动时 `/api/all` 会返回
  `status=warming`，前端要轮询重试——重构时**别把这个降级逻辑丢掉**。
- 筛选池每行是**两行结构**（第二行是"同类 P__ · 组别 · 只对照 · 截至"），抽卡片原语时
  别把它拍平成单行。
- 涨跌/风险语义色只能用 `--up/--down/--warn`，且**动量的"位置条"必须保持中性色**
  （它只表位置不表优劣，见 `docs/参照系接入执行报告.md` §4 的 C2）。
- 表格/列表行高、分隔线 `rgba(255,255,255,.05)`、圆角 12 等细节以 DESIGN.md §3/§4 为准。
