### 2.2 单一事实来源（SSOT）—— 禁止重写这些表达式

| SSOT | 位置 | 内容 |
|:--|:--|:--|
| 估值净值口径 | `src/analysis/nav_series.py` → `VALUATION_NAV_SQL` | `CASE WHEN acc_nav IS NOT NULL AND acc_nav > 0 THEN acc_nav ELSE unit_nav END` |
| 成交定价口径 | 同上（文档部分） | 成交价**只能用 `unit_nav`**，用 `acc_nav` 会买到一个不存在的价格 |
| 指标与分组 | `scripts/calibrate_thresholds.py` → `metrics()` / `TYPE_GROUPS` / `TYPE2GROUP` / `MIN_N_*` | 全项目共用 |
| 无风险利率 | `src/analysis/risk_free.py` | 统一 0.02 |

> ⚠️ **真实教训**：`calibrate_thresholds.py` 曾用朴素 `COALESCE(acc_nav, unit_nav)`，
> 而采集器把缺失的累计净值写成 `0.0` 而非 `NULL` —— `0.0` 不是 NULL，COALESCE 原样返回它，
> 随后 `WHERE > 0` 把整行丢掉，而正确行为是逐行回退 `unit_nav`。
> 结果：参照系与线上推荐**用了两套净值口径**。已修。**不要再手写这个表达式。**

## 四、批次划分

### 批次 A —— 推荐链路落改（必须先做，B/C 依赖它）

**A1. 确立「绝对 vs 相对」的设计原则**（这是本批次的核心判断，需写进代码注释与文档）

- **绝对概念 → 保留绝对限值**：费率上限、回撤容忍度。
  「回撤超过 35% 就不推荐」是一句**风险偏好声明**，不该随同侪分布浮动。
- **相对概念 → 改用组内分位**：「追涨」本质是相对同侪的。
- 依据：上一批次实测「常数是 P75 的严格超集」，说明换分位不改变选出谁；
  但同一个 `35` 在 A 组淘汰 19%、在 E 组只淘汰 0.2% —— **跨组强度完全不一致**。

**A2. `momentum_warning`：40（常数）→ 组内 P90（分位）**

- 理由：实测失效（通过率 99.3~100%），且「追涨」是相对概念
- 落点：`src/analysis/fund_scorer.py:292`
- **要求**：必须显式标注「本项目自定阈值，依据是实测分布而非文献」

**A3. `max_total_fee` 口径修正**

- 现状 bug：`custodian_fee` 源头不可得且恒为 0，于是「总费率 = 管理费 + 0」被系统性算低 → **该阈值永不触发**
- 修法：**口径改为「仅管理费」**，并按新口径重新定位阈值
  - 新值需要用 `fund_info.mgt_fee`（98.0% 填充）的实测分布来定，**不得沿用旧值 2.0**
  - 依据：`docs/_thresholds.txt` 与 `scripts/relocate_thresholds.py` 的方法
- **禁止**：用某个常数冒充托管费（违反铁律 5）

**A4. 确认 3 个「复活」字段真的生效**

- `min_size_yi` / `max_size_yi` ← `fund_size`（现 66.9%，覆盖池内 99.7%）
- `min_manager_years` ← `manager_tenure`（现 67.0%）
- **要求**：写一个实测脚本，统计修前/修后**通过率与被动淘汰数**的变化。
  若「规模」阈值在修复前会因 `fund_size=None` 静默放行全部基金，必须把这一点写成证据。

**A5. `max_drawdown_1y`**

- 保留为**绝对门槛**（见 A1），但必须在该常量旁注释**实测的跨组位置**：
  A P81 / B P86 / C P82 / D P94 / E P100 / F P96，
  并明说「在 D/E/F 组它几乎不设限」

**A6. 补测试**（硬要求）

- `tests/` 下新增：分位阈值生效、费率口径、样本不足路径、组别归属
- **334 个既有测试必须全绿**

### 批次 B —— 参照系接入 API

**B1. 把组内百分位接进输出**

- 数据来源：`scripts/fund_percentile.py` 已有完整实现（组内分布 → 每只基金百分位）
- **要求**：不要在 `src/` 里重新实现一遍 —— 若需要进程内调用，
  把 `fund_percentile.py` 的计算下沉为一个可复用的函数/模块，**脚本与 API 共用同一实现**
  （这是 SSOT 铁律的直接应用：本项目已经因为「两处各写一遍」栽过跟头）

**B2. 样本不足必须显式声明**

- R3 的 **6,856 只**存续不足 3 年 → **不给百分位，且必须说明**
- 输出字段建议：`percentile: null, insufficient_data: true, reason: "存续不足3年"`
- **反例警告**：本项目已有前车之鉴 —— 审计发现「五个维度全部缺失，界面仍给出『市场温度 50.0° 适中』」。
  **宁可显示「数据不足」，也不要显示一个具体数字。**

**B3. R4 定开基金门槛修正**

- 现状：门槛按**点数** ≥756 算，导致 387 只定开基金被误排
  （如 `000792` 招商定期宝六个月期理财债券：**跨度 3,374 天、仅 591 点**）
- 建议：`点数 ≥ 756` **或**（`日历跨度 ≥ 3 年` **且** `点数 ≥ 250`）
- **要求**：改完必须重跑 `scripts/audit_coverage.py`，报告覆盖率变化（预计 61.2% → 约 63%）
- 并说明为何对定开基金用稀疏净值是**正确的**（持有人本来也只能在开放日赎回）

**B4. 接口字段**

- `/api/funds/board`、`/api/recommend` 输出增加：
  `group`（组别）、`group_n`（组内样本量）、`percentiles`（各指标）、`nav_asof`（数据日期）
- **要求**：保持向后兼容（新增字段，不改动既有字段语义）

**B5. 用 `peer_pct` 做回归基线**（高价值，别漏）

- `fund_profile_extra.peer_pct` 是天天基金自己的同类百分位，与我们完全独立
- **要求**：把上一批次的验证脚本 `scripts/validate_vs_source.py` 纳入常规检查，
  作为参照系改动的**回归哨兵**。若某次改动让 ρ 明显下降，说明口径被改坏了。
