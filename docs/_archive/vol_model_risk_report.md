# 基金波动率预测模型 — 问题风险报告（立项初期审查）

> 生成时间: 2026-09-08
> 触发: vol_predictor.py 第一版（XGBoost 单模型）上线后的第一性原理复盘
> 审查框架: `.claude/skills/first-principles-review.md` v2.6

## 一、痛点优先检查

- **痛点是谁**: 自用量化工具用户，月度调仓前需要预判下月波动率做仓位调整
- **为什么发生**: 温度计是反应式（看当前估值分位），无前瞻风险预判；回撤发生时已晚
- **真实性**: 自用场景不收钱，但降回撤 6.6pp（21.37%→14.73%）有体验价值 ✅

## 二、第一性原理

- **拆解**: 核心=用 t 月末及之前数据预测 t+1 月日收益波动率。删掉 ML → 退化为 EWMA 基线（仍能跑，IC 0.771），ML 增量价值=IC +0.027
- **因果链**: vol 聚类是因果基础。**关键发现**: 特征重要度 top3（ewma_vol 0.30 + vol_1m 0.19 + vol_rank_pct 0.14 = 0.63）全是 vol 历史的变体 → 因果链本质上只有一条"vol 持续性"
- **删除测试**: 删掉 14 个非 vol 历史特征 → IC 大概率只降到 0.77（EWMA 水平）。**那 14 个特征可能是装饰品**

## 三、对抗式审查

1. **假设**: 最核心假设="ML 能提供超越 vol 聚类的增量信号"。**实测打脸**: 增量 IC 仅 0.027（3.5%），且 hs300_pe_pct 重要度=0.0000，宏观特征全部失效
2. **数据**: ✅ 本地 DB 已实测，无新数据源风险
3. **替代**: **HAR-RV（Corsi 2004）——3 特征 OLS（日/周/月 vol 回归）**——是学术界 vol 预测标准，未跑对比。这是最大的替代漏洞
4. **规模**: ✅ 8339 样本，但因 vol 高自相关，**有效独立样本量远小于 8339**（规则8 隐患）
5. **叙事**: 一句话能讲清，但"ML 增量 3.5%"这个数字在答辩时会被追问"是否在噪声内"

## 五、XGBoost 选择的根因复盘

### 表面理由（当时给出的）
1. 处理混合特征类型好
2. 内置正则化
3. 处理缺失值
4. 适合中等样本量

### 真实原因（实际推理链）
1. **用户的优先级列表里第一个就写了 "XGBoost"** —— 跟了用户的话，没有独立判断
2. **XGBoost 是表格数据的"ML 默认值"** —— 没有强约束时抓最近的标准工具
3. **"补全 ML 能力"这个目标锚定了"必须用 ML"** —— 用线性回归就不算"补全 ML"
4. **没装 arch 库** —— 本想用 GARCH-X，装不上就退到 XGBoost，但没退到 HAR-RV

### 为什么这些理由站不住

**1. 这个问题本质是自回归，不是横截面 ML**
- 预测 vol_{t+1} 从 vol_t 及其滞后 → 这是 AR 过程
- XGBoost 把每个 (fund, month) 当独立行，丢失了面板时序结构
- 时间序列模型（GARCH/HAR-RV/AR）才是自然选择
- 特征重要度已经证明：top 3 全是 vol 历史，XGBoost 学的是"加权的 EWMA"

**2. 特征重要度是 XGBoost 选择错误的铁证**
```
ewma_vol      0.2994  ← 基线本身
vol_1m        0.1893  ← vol 历史
vol_rank_pct  0.1398  ← vol 历史的横截面 rank
─────────────────────
合计          0.6285  ← 63% 重要度全来自 vol 持续性
```
- 剩下 12 个特征（含所有宏观/高矩/规模）合计 37%，且 `hs300_pe_pct` = 0.0000
- **XGBoost 本质是 EWMA + 噪声调整**

**3. 规则8 被违反：有效样本量远小于 8339**
- vol 高度自相关（月度 vol 的 AR(1) 系数通常 >0.9）
- 有效独立样本 ≈ 8339 / (1+ρ)/(1-ρ) 这种修正后可能只有几百
- 15 个特征中 vol_1m/vol_3m/vol_6m/ewma_vol 两两 r>0.8 → 实际独立信号 ≈3-4 个
- **3-4 个有效信号 + 几百有效样本 → 用 OLS 就够，XGBoost 的非线性能力没有发挥空间**

**4. 规则12 被违反：没做实测对比就选了模型**
- 应该先跑的对比顺序（从简单到复杂）:
  1. EWMA (1 参数) → IC 0.771 ✅ 跑了
  2. **HAR-RV (3 参数 OLS)** → 没跑 ❌ **这是最大遗漏**
  3. Ridge 回归 (15 特征 + L2) → 没跑 ❌
  4. XGBoost → 跑了，IC 0.798
- **如果 HAR-RV 的 IC 是 0.79，XGBoost 就是多余的**
- 学术界 vol 预测的标准基线是 HAR-RV，不是 EWMA

## 六、综合结论

- **综合信心**: 55%（从初版 78% 下调——读到特征重要度后发现问题）
- **最致命一击**: 特征重要度证明 XGBoost 本质是"带 14 个装饰特征的 EWMA"，ML 增量 0.027 IC 很可能在噪声内
- **最没把握的事**[规则9]: 0.027 IC 增量是否统计显著（未做排列检验）
- **最大遗漏**[规则10]: 没跑 HAR-RV（Corsi 2004）这个学术界 vol 预测标准模型作为第三基线
- **题目锚定**[规则13]: "补全 ML 能力"与"vol 预测业务问题"目标冲突——vol 预测问题本身不需要 ML
- **建议**: **修正——补跑 HAR-RV 基线 + 排列检验 + 多模型对比，否则"XGBoost 跑过基线"的结论不可信**

## 七、下一步行动项

1. **补跑 HAR-RV（Corsi 2004）作为第三基线**
   - 3 特征（日/周/月已实现 vol），OLS，无超参
   - 学术界 vol 预测标准，3 分钟跑完
2. **多模型对比（3-4 个模型同口径实测）**
   - HAR-RV / Ridge / XGBoost / LightGBM（或 RF 作为 LightGBM 不可用时的降级）
3. **排列检验（Permutation Test）**
   - 对每个 ML 模型相对 EWMA 的 IC 增量做显著性检验
4. **GitHub 调研开源项目**
   - 参考 `volatility-forecasting` / `financial-ML` 类项目的特征工程与验证方法
5. **自动化多模型测试管道**
   - 一键跑全部模型 + 生成对比报告
6. **若 HAR-RV ≥ XGBoost**，则诚实地把"主模型"改成 HAR-RV，XGBoost 降级为"对比实验"——这反而是更扎实的研究叙事
