═══════════════════════════════════════════════════════════════
SSOT：这些表达式禁止重新手写
═══════════════════════════════════════════════════════════════

- 估值序列口径 → src\analysis\nav_series.py 的 VALUATION_NAV_SQL
  `CASE WHEN acc_nav IS NOT NULL AND acc_nav > 0 THEN acc_nav ELSE unit_nav END`
- 成交定价 → **只能用 unit_nav**（用 acc_nav 会买到一个不存在的价格）
- 指标与分组 → scripts\calibrate_thresholds.py 的 metrics() / TYPE_GROUPS
- 无风险利率 → src\analysis\risk_free.py（统一 0.02）

⚠️ 真实教训：calibrate_thresholds.py 曾手写朴素 `COALESCE(acc_nav, unit_nav)`，
而采集器把缺失的累计净值写成 0.0 而不是 NULL —— 0.0 不是 NULL，COALESCE 原样返回它，
随后 `WHERE > 0` 把整行丢掉，正确行为却是逐行回退 unit_nav。
结果参照系和线上推荐**用了两套净值口径**。改口径时先找 SSOT，别就地重写。

── 批次 A：推荐链路落改（必须先做，B/C 依赖它）──

核心设计判断（这是本批次最该想清楚的一件事）：
  · **绝对概念 → 保留绝对限值**：费率上限、回撤容忍度。「回撤超过 35% 就不推荐」
    是一句风险偏好声明，不该随同侪分布浮动。
  · **相对概念 → 改用组内分位**：「追涨」本质是相对同侪的。
  依据：实测「常数阈值选出的集合是 P75 的严格超集，重合 100%」→ 换分位**不改变选出谁**；
  但同一个 35 在 A 组淘汰 19%、在 E 组只淘汰 0.2%，**跨组强度完全不一致**。

A1. `momentum_warning` 40（常数）→ 组内 P90（分位），落点 fund_scorer.py:292
A2. `max_total_fee` 口径改为「仅管理费」，并用 `fund_info.mgt_fee`（98.0% 填充）
    的**实测分布**重新定位阈值 —— **不得沿用旧值 2.0，也不得拿常数冒充托管费**
A3. 验证刚补齐的字段真的生效：统计 `min_size_yi`/`max_size_yi`（← fund_size）、
    `min_manager_years`（← manager_tenure）在修复前后的**通过率与被动淘汰数变化**。
    如果修复前 `fund_size=None` 会静默放行全部基金，把这一点写成证据
A4. `max_drawdown_1y` 保留为绝对门槛，但注释写明实测跨组位置
    （A P81 / B P86 / C P82 / D P94 / E P100 / F P96），并明说「在 D/E/F 组几乎不设限」
A5. **补测试**：分位阈值生效、费率口径、样本不足路径、组别归属
