## 2. 目标命题与架构

### 2.1 题目（已定）

《基于多源金融数据的个人基金投资决策支持系统》

> 原题《…交易行为分析与建模》本身没错，错的是实现。"分析与建模"= 行为度量 + 市场风险建模，都保留为正文；"决策支持"是落点。
> ⚠️ **"系统"二字是过度承诺（规则 13）**：只有 1 个 pilot 用户，非多用户部署。论文里"系统"解释为"分析能力 + 决策支持输出"，并诚实声明「系统 vs 实例」边界。

### 2.2 架构（四层）

```
L4 决策支持应用层   前端「决策台」：行为镜 + 四信号 + 反事实；账本工具；数据状态
L3 行为分析引擎     任意用户账本 → 行为度量 + 反事实（小样本友好，只读）
L2 市场建模         用户无关共享服务：波动率/回撤/同类分位/排雷（真 ML 在这里）
L1 多源数据平台     系统数据：采集→治理→分层→PIT 特征（2290万行，共享）
```

### 2.3 产品契约优先级

> ⚠️ **优先级（规则 3）**：行为镜 + 反事实 = **一等交付物**（对应题目"行为分析"）；四信号 = **二等上下文**（对应"多源金融数据"）。前后端与论文都按这个权重，不要并列。
> ⚠️ **"排雷/风险"隐含可辩护的预测（规则 2）**：波动率可预测、bottom decile 剔除显著——这是**可辩护预测**，与"收益/alpha 预测"（不可辩护）划清界限，论文显式声明。

### 3.6 `GET /api/peer` 契约

后端逻辑：对当前持仓每只基金：
1. `cache = peer_percentile.load_cache()`；若 `cache is None` → 整体返回 `{"error": "同类参照系未构建，请先跑 build_distributions"}`（**不猜**）。
2. 取 `fund_type`（`fund_info`）、`group = peer_percentile.group_of(fund_type)`；组未映射 → 该基金 `insufficient_data:true, reason:"类型未映射到参照系组"`。
3. 算该基金 `sharpe` / `max_drawdown_1y` / `ter`（前两者用 `nav_metrics.compute`，`ter` 用 `fund_fee.compute_ter(fund_info 行)`）。
