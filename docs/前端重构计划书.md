## 1. 为什么推倒重来（诊断，2026-09-27）

### 1.1 旧前端的结构性问题

| 问题 | 实测 |
|---|---|
| 渲染逻辑全在浏览器手写拼串 | `app.js` **1385 行**，靠模板字符串拼 HTML |
| 双路径分叉 | 同一份展示逻辑被前后端各写一遍（踩过：口径不一致） |
| 首屏等 JS | 页面骨架也是 JS 拼出来的，白屏时间 = 全量 JS 解析时间 |
| 难测 | 无组件边界；本会话验证靠"真实载荷 + node 截函数真跑"（4/4 通过） |
| Jinja2 闲置 | `templates/` 只有 1 个空壳 `dashboard.html` |

### 1.2 一个**功能性错误**（不只是审美）

`app.css` 的涨跌色是**欧美惯例**：`--up:#27a644`（绿=涨）/ `--down:#e5484d`（红=跌）。
中国惯例是**涨红跌绿**（同花顺，`FenshiChart` 明确写"中国A股风格：涨为红色、跌为绿色"）。
→ 旧界面满屏"涨了显示绿、跌了显示红"。

新前端对策：命名**用 rise/fall 而不是 up/down**（up/down 在两种惯例下颜色相反，是这次事故的词源），
并在 `src/lib/format.ts` 收成**唯一**的方向判定与取色入口。

### 2.2 Token 表 v2（`frontend/src/index.css` `@theme`，2026-09-30 视觉升级）

> v1（`#0e1117` 系）已废弃。v2 的依据是**直接读 GitHub 源码**（不是设计博客）：
> `shadcn-ui/ui` 的 `app/globals.css`（暗色变量）、`ghostfolio/ghostfolio` 的 `apps/client/src/styles.scss`。

| 组 | 值 | 规则 |
|---|---|---|
| 层级 | canvas `#090c12` < card `#131922` < inset `#1a212c` | 明度阶梯比例对齐 shadcn 的 oklch L 0.145 / 0.205 / 0.269 |
| **边框** | line = **`rgba(154,178,214,.10)`**；strong = `.20` | 取自 shadcn 的 `oklch(1 0 0 / 10%)`：**半透明**边框在 canvas/card/inset 上都自适应，实色只在特定底色上成立 |
| 文本 | fg `#e9eff7` → 2 `#a2b0c4` → 3 `#7a8799` → 4 `#596476` | 层级按 Ghostfolio/Material 的 **alpha 阶梯**（.87 / .70 / .50 / .38）收，不随手挑四个灰 |
| 强调 | accent `#5aa2ff` + accent-2 `#8b6cff` | 主蓝→次紫用于品牌标与顶部柔光；暗底下降饱和 |
| **涨跌** | **rise `#ff6b5e`（涨=红）/ fall `#34c76a`（跌=绿）** | **中国惯例（不变项）**；配合 ▲▼ 符号（色盲硬约束） |
| 状态 | warn `#e3b341` / flat `#8b97a8` | — |
| 画布 | canvas 底色 + **四团极光**（蓝 / 紫 ×2 / 青，`background-attachment: fixed`）+ **颗粒噪点**（SVG `feTurbulence` 平铺） | 大面积暗色**不能是纯色**：纯色显死，且在显示器上会出现色带 |
| **卡片** | **磨砂玻璃**：`rgba(20,27,38,.70)` + `backdrop-filter: blur(16px) saturate(140%)` | 半透明让底部极光透上来，卡片与背景产生交互，而不是"贴上去的一块砖" |

**表面处理**（收在 `index.css` 的 `.surface` / `.surface-lead` / `.glass`，组件只给内边距）：
顶部内高光渐变 + 1px 半透明边框 + 大而软的阴影；结论卡额外加**左侧渐变强调条**
（用 `::before` 而不是 `border-image` —— 后者会接管全部四条边，与"只强调左侧"的意图相反）
+ 内外两层极光。

> 🩹 **一次真实返工（值得记）**：v2 的极光只有 2 团、透明度 0.10 —— 整页截图里几乎看不见，
> 用户直接反馈「背景除了卡片都是纯黑」。根因是**透明度太低 + 只集中在顶部**。
> ⚠️ 验收方法也要记：`background-attachment: fixed` 的背景在**整页截图**里只渲染顶部一屏，
> **必须用视口截图验收**，否则会得出错误的"已经够了"结论（本轮就是这么发现的）。

**全局微交互 / 无障碍**（同样取自 shadcn/ui 的 `@layer base`）：
`button:active{opacity:.72}`、`::selection` 配色、`overscroll-behavior-y:none`、
`font-synthesis-weight:none`（防止浏览器假装字重）、**`scroll-padding-top:64px`**（吸顶导航必需，
否则锚点会被导航盖住）、`:focus-visible` 焦点环、卡片入场动画 `rise-in`
且尊重 `prefers-reduced-motion`。

**数据可视化（曲线卡）的两条硬要求**（2026-09-30 实测补）：
1. **零轴必须与网格明显区分且带标签** —— 网格压到 `#1c2532` 虚线，零轴用 `#5f7488` 实线 1.6px；
   Y 轴范围**显式给数**（`domain={[lo,hi]}`，不用函数式）+ 刻度由 `niceTicks()` 生成并**强制含 0**。
   > 踩坑：Recharts 自动刻度在 `[-3.3%, 2.0%]` 上取到 `2.0 / -1.3 / -3.3`，**跳过了 0** ——
   > 零轴画出来了却没有对应标签，"盈亏分界"就还是读不出来。这是"零线不明显"的真正根因，
   > 不是线不够亮。
2. **面积填充以 0 为基线**（`baseValue={0}`），于是负收益区是"零轴下方的填充"而非"利润面积"。

### 2.3 两条硬规则（写死在代码里，不靠自觉）

1. **方向与取色只在 `src/lib/format.ts` 定义一次**（`dirOf` / `dirSymbol` / `dirClass`）。
   各组件禁止自己判断正负再选颜色。
2. **文案清洗只在 `plainText()`**：剥 emoji（后端 `level_desc` 的 🌤️）
   与 markdown 记号（后端 `scope_note` 的 `**适用**`）。

## 3. 技术选型（定案与偏差）

**定案**：React 19 + Vite + TypeScript + Tailwind + shadcn/ui + Recharts。

- **否决 Svelte**（更优雅）：Svelte 5 runes 资料少，出错率高 —— 对"AI 维护"前提，**可靠 > 优雅**。
- **Recharts** 胜出：调研里欧美仪表盘的事实标准；与 React 集成成本最低。

**与定案的偏差（如实记录）**：**shadcn/ui 暂未引入**。理由：当前所需组件（Card / 分段按钮 /
表格）都是十余行的小件，手写更少依赖；shadcn CLI 初始化需要交互式配置。
**何时引入**：需要 Dialog / Tabs / Toast / Combobox 这类有交互状态的复杂组件时。

## 5. API 契约（前端必须处理的三条后端约定）

后端（`src/web/app.py`）的三条约定**全部收拢在 `api/client.ts`**，页面不直接写 URL：

1. **统一包装** `{ok, data, source}`；`ok=false` 时 `error` 是给人看的中文原因。
2. **预热约定**：慢端点冷启动返回 `{ok:true, data:null, status:"warming", retry_in:N}` ——
   调用方按 `retry_in` 轮询。**「还在算」≠「没数据」**（把前者当后者会误报"算出来是空的"）。
3. **`source` 如实标注**（内存缓存 / 本地快照 / 刚重算）——用户拿它判断数字新鲜度。

### 端点 → 组件映射

| 端点 | 页面消费 | 备注 |
|---|---|---|
| `GET /api/overview` | KPI 四格 / 曲线 / 持仓表 / 温度卡 | `holdings` 是**批次行**（29 行 = 7 只基金），前端负责聚合后再显示 |
| `GET /api/rebalance` | 结论卡（verdict + 指令 + 口径声明） | 权益占比是**温度适用的 A 股口径**（另有 `non_applicable_pct` 不参与判断） |
| `GET /api/explain` | 数据链路五格（采集→清洗→特征→建模→评估） | 每格 `rows`（明细）+ `artifacts`（真实产物：落库表/脚本/报告） |

### 7.1 阶段 2 实测记录（2026-09-30）

方法：**真浏览器**（Playwright + system Python，`channel="chrome"` headless），
用 `page.route` 拦截 `/api/*` 注入异常载荷；移动端量 `scrollWidth vs clientWidth` +
元素级溢出扫描。脚本与截图在仓库外 `D:\DSH\scratch_hold\_v2_*.py`。

| # | 场景 | 注入载荷 | 实测结果 |
|---|---|---|---|
| A | 正常 | 无 | 整页渲染，console 0 error |
| B | 预热 | `{ok:true,data:null,status:"warming",retry_in:7}` | 「正在计算…还需约 7 秒」横幅 ✅ —— **没把"还在算"显示成"没有数据"** |
| C | 失败 | `{ok:false,error:"数据库正被占用…"}` | 「读取失败：<后端中文原因>」+ 重试 ✅ |
| D | 空数据 | `{ok:true,data:null}`（非预热） | 「读取失败：后端返回了空数据（非预热）」✅ —— 不白屏、不静默 |
| E | 空持仓 | 真实载荷但 `holdings=[]` | ❌→✅ 原为**只剩表头**的空表；已补空态文案 |
| F | 调仓端点单独失败 | 只拦 `/api/rebalance` 为 `ok:false` | ❌→✅ 原只说「调仓结论暂不可用」（无原因）；已上屏后端原因 |
| G | 移动端 375/414/768 | — | 三种宽度**零横向溢出**（元素级扫描 0 命中）✅ |

据此修掉三处（本轮交付，2026-09-30）：

1. **持仓表空态**（`HoldingsTable.tsx`）：`shown` 为空时区分「真的没有在持基金」与
   「被盈利/亏损筛选滤空（提示切回全部可见 N 只）」——原先两种都只画表头。
2. **调仓失败原因上屏**（`VerdictCard.tsx` + `Today.tsx`）：原先只处理 `overview.error`，
   `/api/rebalance` 单独失败时用户无从知道为什么；现按本项目约定带出后端中文原因。
3. **`/api/explain`「适用边界」不再是 Python 字面量**（`app.py::_scope_text`，计划书 §9.2）：
   原为 `str(scope)[:80]` → 界面出现 `{'applies_to': [...]}` 且被截断；
   现渲染为「适用 A 股权益（…）；不适用 债券型 / 货币型 / QDII-海外 / 商品/黄金 / Reits」。

> ⚠️ **踩坑（值得记）**：后端三条端点都有**落盘快照**缓存（`analysis_snapshot`）。
> 改了后端代码后页面仍读旧载荷，必须 `?fresh=1` 触发重算 —— 第一轮复核就因此误判为"修复没生效"。
> 另：`page.route` 注入的载荷必须是**完整信封** `{ok,data}`，只给 `data` 本体会被前端判成 `ok=false`。

### 7.5 交互动效（2026-09-30 第四批）

用户：「还有一些互动的动态效果，也可以酌情加到里面」。

**原则：动效用来解释状态，不是装饰** —— 每条都要能说出它解决了什么问题，说不出来就不加。

| 动效 | 解决什么 | 实现 |
|---|---|---|
| 卡片**错峰**入场 | 整屏卡片"唰"地同时出现是最廉价的效果；错峰让眼睛按阅读顺序接收 | `main > :nth-child(k)` 依次 0/60/120/180/240/300/360ms |
| 收益曲线**依次绘制** | 两条线同时画完就看不出"谁先偏离" | 本组合 0ms、沪深300 延后 260ms，各 950ms ease-out |
| 建仓进度条**从左侧长出** | 静态满条读不出"已经投了多少" | `.grow-x`（`transform: scaleX` 走合成层，不触发重排） |
| 温度尺**指针滑入** | 指针直接出现，读不出它"落在哪一档" | `.slide-thumb` 从 `left:0` 滑到目标位 |
| **骨架屏**替代「加载中…」 | 一行字没有信息量；骨架给出内容的"形状" | `.skeleton` shimmer；容器 `aria-hidden` + `sr-only` 文案，避免读屏重复播报 |
| 表格行 hover **左侧极光** | 长表格里"跟住一行" | `.row-hover:hover` 左侧渐变 |

⚠️ **两条纪律（都踩过或差点踩）**：
1. `.rise-in` 必须用 **`fill-mode: backwards`** 而不是 `both` ——
   `forwards` 会把 `transform` 永久钉在 keyframe 上，之后任何 hover 变换都会**静默失效**。
2. **卡片不做 hover"抬起"** —— 卡片不是可点元素，抬起会暗示可点击，是误导。
   卡片 hover 只改边框亮度。

**验收（新增探针，8/8 通过）**：动效**不能靠静态截图验收**，改为读**计算样式** ——
错峰延迟实测 `0s / 0.06s / 0.12s / 0.18s / 0.24s`；`animation-name` 分别为
`qfa-rise` / `qfa-grow` / `qfa-slide-thumb` / `qfa-shimmer`；注入 warming 后骨架屏确实出现；
`prefers-reduced-motion: reduce` 下入场动画为 `none`。脚本 `D:\DSH\scratch_hold\_v6_anim.py`。
