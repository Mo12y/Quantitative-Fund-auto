## 1. 为什么推倒重来（诊断，2026-09-27）

### 1.1 旧前端的结构性问题

| 问题 | 实测 |
|---|---|
| 渲染逻辑全在浏览器手写拼串 | `app.js` **1385 行**，靠模板字符串拼 HTML |
| 双路径分叉 | 同一份展示逻辑被前后端各写一遍（踩过：口径不一致） |
| 首屏等 JS | 页面骨架也是 JS 拼出来的，白屏时间 = 全量 JS 解析时间 |
| 难测 | 无组件边界；本会话验证靠"真实载荷 + node 截函数真跑"（4/4 通过） |
| Jinja2 闲置 | `templates/` 只有 1 个空壳 `dashboard.html` |

### 1.2 一个**功能性错误**（不只是审美）

`app.css` 的涨跌色是**欧美惯例**：`--up:#27a644`（绿=涨）/ `--down:#e5484d`（红=跌）。
中国惯例是**涨红跌绿**（同花顺，`FenshiChart` 明确写"中国A股风格：涨为红色、跌为绿色"）。
→ 旧界面满屏"涨了显示绿、跌了显示红"。

新前端对策：命名**用 rise/fall 而不是 up/down**（up/down 在两种惯例下颜色相反，是这次事故的词源），
并在 `src/lib/format.ts` 收成**唯一**的方向判定与取色入口。

### 2.2 Token 表 v2（`frontend/src/index.css` `@theme`，2026-09-30 视觉升级）

> v1（`#0e1117` 系）已废弃。v2 的依据是**直接读 GitHub 源码**（不是设计博客）：
> `shadcn-ui/ui` 的 `app/globals.css`（暗色变量）、`ghostfolio/ghostfolio` 的 `apps/client/src/styles.scss`。

| 组 | 值 | 规则 |
|---|---|---|
| 层级 | canvas `#090c12` < card `#131922` < inset `#1a212c` | 明度阶梯比例对齐 shadcn 的 oklch L 0.145 / 0.205 / 0.269 |
| **边框** | line = **`rgba(154,178,214,.10)`**；strong = `.20` | 取自 shadcn 的 `oklch(1 0 0 / 10%)`：**半透明**边框在 canvas/card/inset 上都自适应，实色只在特定底色上成立 |
| 文本 | fg `#e9eff7` → 2 `#a2b0c4` → 3 `#7a8799` → 4 `#596476` | 层级按 Ghostfolio/Material 的 **alpha 阶梯**（.87 / .70 / .50 / .38）收，不随手挑四个灰 |
| 强调 | accent `#5aa2ff` + accent-2 `#8b6cff` | 主蓝→次紫用于品牌标与顶部柔光；暗底下降饱和 |
| **涨跌** | **rise `#ff6b5e`（涨=红）/ fall `#34c76a`（跌=绿）** | **中国惯例（不变项）**；配合 ▲▼ 符号（色盲硬约束） |
| 状态 | warn `#e3b341` / flat `#8b97a8` | — |
| 画布 | canvas 底色 + **四团极光**（蓝 / 紫 ×2 / 青，`background-attachment: fixed`）+ **颗粒噪点**（SVG `feTurbulence` 平铺） | 大面积暗色**不能是纯色**：纯色显死，且在显示器上会出现色带 |
| **卡片** | **磨砂玻璃**：`rgba(20,27,38,.70)` + `backdrop-filter: blur(16px) saturate(140%)` | 半透明让底部极光透上来，卡片与背景产生交互，而不是"贴上去的一块砖" |

**表面处理**（收在 `index.css` 的 `.surface` / `.surface-lead` / `.glass`，组件只给内边距）：
顶部内高光渐变 + 1px 半透明边框 + 大而软的阴影；结论卡额外加**左侧渐变强调条**
（用 `::before` 而不是 `border-image` —— 后者会接管全部四条边，与"只强调左侧"的意图相反）
+ 内外两层极光。

> 🩹 **一次真实返工（值得记）**：v2 的极光只有 2 团、透明度 0.10 —— 整页截图里几乎看不见，
> 用户直接反馈「背景除了卡片都是纯黑」。根因是**透明度太低 + 只集中在顶部**。
> ⚠️ 验收方法也要记：`background-attachment: fixed` 的背景在**整页截图**里只渲染顶部一屏，
> **必须用视口截图验收**，否则会得出错误的"已经够了"结论（本轮就是这么发现的）。

**全局微交互 / 无障碍**（同样取自 shadcn/ui 的 `@layer base`）：
`button:active{opacity:.72}`、`::selection` 配色、`overscroll-behavior-y:none`、
`font-synthesis-weight:none`（防止浏览器假装字重）、**`scroll-padding-top:64px`**（吸顶导航必需，
否则锚点会被导航盖住）、`:focus-visible` 焦点环、卡片入场动画 `rise-in`
且尊重 `prefers-reduced-motion`。

**数据可视化（曲线卡）的三条硬要求**（2026-09-30 起两批实测后定稿）：

1. **坐标系必须是完整的**（2026-10-01 修）：**双向网格**（实测垂直 7 条 / 水平 8 条）
   + **两条坐标轴线**（左 + 下）+ X 轴短日期（`MM-DD`，用 `interval` 把标签控到 ~7 个）
   + Y 轴 6 档。
   > 实测旧版：**垂直网格 0 条、轴线 0 条、X 轴是 10 字符的完整日期** ——
   > 用户反馈"没有坐标轴没有参考系，读起来有点困难"。
   > **参考系是折线图的地基，不能为了"干净"把它压没。**
2. **零轴必须与网格明显区分且带标签**：网格 `#202a37` 虚线；零轴 `#7b8fa6` **实线 1.6px**（全图最强）。
   Y 轴范围**显式给数**（`domain={[lo,hi]}`，不用函数式）+ 刻度由 `niceTicks()` 生成并**强制含 0**。
   > 踩坑一：Recharts 自动刻度在 `[-3.3%, 2.0%]` 上取到 `2.0 / -1.3 / -3.3`，**跳过了 0** ——
   > 零轴画出来了却没有对应标签，"盈亏分界"就还是读不出来。
   > 踩坑二：`niceTicks` 早先写的是"取最小的 ≥ raw 的漂亮档位"，在 span≈6 时直接跳到 step=2、
   > 只剩 3 条线 —— **网格太稀等于没有参考系**。改为"选刻度条数最接近目标（6）"的档位。
3. **面积填充以 0 为基线**（`baseValue={0}`），于是负收益区是"零轴下方的填充"而非"利润面积"。

### 2.3 两条硬规则（写死在代码里，不靠自觉）

1. **方向与取色只在 `src/lib/format.ts` 定义一次**（`dirOf` / `dirSymbol` / `dirClass`）。
   各组件禁止自己判断正负再选颜色。
2. **文案清洗只在 `plainText()`**：剥 emoji（后端 `level_desc` 的 🌤️）
   与 markdown 记号（后端 `scope_note` 的 `**适用**`）。

## 3. 技术选型（定案与偏差）

**定案**：React 19 + Vite + TypeScript + Tailwind + shadcn/ui + Recharts。

- **否决 Svelte**（更优雅）：Svelte 5 runes 资料少，出错率高 —— 对"AI 维护"前提，**可靠 > 优雅**。
- **Recharts** 胜出：调研里欧美仪表盘的事实标准；与 React 集成成本最低。

**与定案的偏差（如实记录）**：**shadcn/ui 暂未引入**。理由：当前所需组件（Card / 分段按钮 /
表格）都是十余行的小件，手写更少依赖；shadcn CLI 初始化需要交互式配置。
**何时引入**：需要 Dialog / Tabs / Toast / Combobox 这类有交互状态的复杂组件时。

## 5. API 契约（前端必须处理的三条后端约定）

后端（`src/web/app.py`）的三条约定**全部收拢在 `api/client.ts`**，页面不直接写 URL：

1. **统一包装** `{ok, data, source}`；`ok=false` 时 `error` 是给人看的中文原因。
2. **预热约定**：慢端点冷启动返回 `{ok:true, data:null, status:"warming", retry_in:N}` ——
   调用方按 `retry_in` 轮询。**「还在算」≠「没数据」**（把前者当后者会误报"算出来是空的"）。
3. **`source` 如实标注**（内存缓存 / 本地快照 / 刚重算）——用户拿它判断数字新鲜度。

### 端点 → 组件映射

| 端点 | 页面消费 | 备注 |
|---|---|---|
| `GET /api/overview` | KPI 四格 / 曲线 / 持仓表 / 温度卡 | `holdings` 是**批次行**（29 行 = 7 只基金），前端负责聚合后再显示 |
| `GET /api/rebalance` | 结论卡（verdict + 指令 + 口径声明） | 权益占比是**温度适用的 A 股口径**（另有 `non_applicable_pct` 不参与判断） |
| `GET /api/explain` | 数据链路五格（采集→清洗→特征→建模→评估） | 每格 `rows`（明细）+ `artifacts`（真实产物：落库表/脚本/报告） |

### 7.1 阶段 2 实测记录（2026-09-30）

方法：**真浏览器**（Playwright + system Python，`channel="chrome"` headless），
用 `page.route` 拦截 `/api/*` 注入异常载荷；移动端量 `scrollWidth vs clientWidth` +
元素级溢出扫描。脚本与截图在仓库外 `D:\DSH\scratch_hold\_v2_*.py`。

| # | 场景 | 注入载荷 | 实测结果 |
|---|---|---|---|
| A | 正常 | 无 | 整页渲染，console 0 error |
| B | 预热 | `{ok:true,data:null,status:"warming",retry_in:7}` | 「正在计算…还需约 7 秒」横幅 ✅ —— **没把"还在算"显示成"没有数据"** |
| C | 失败 | `{ok:false,error:"数据库正被占用…"}` | 「读取失败：<后端中文原因>」+ 重试 ✅ |
| D | 空数据 | `{ok:true,data:null}`（非预热） | 「读取失败：后端返回了空数据（非预热）」✅ —— 不白屏、不静默 |
| E | 空持仓 | 真实载荷但 `holdings=[]` | ❌→✅ 原为**只剩表头**的空表；已补空态文案 |
| F | 调仓端点单独失败 | 只拦 `/api/rebalance` 为 `ok:false` | ❌→✅ 原只说「调仓结论暂不可用」（无原因）；已上屏后端原因 |
| G | 移动端 375/414/768 | — | 三种宽度**零横向溢出**（元素级扫描 0 命中）✅ |

据此修掉三处（本轮交付，2026-09-30）：

1. **持仓表空态**（`HoldingsTable.tsx`）：`shown` 为空时区分「真的没有在持基金」与
   「被盈利/亏损筛选滤空（提示切回全部可见 N 只）」——原先两种都只画表头。
2. **调仓失败原因上屏**（`VerdictCard.tsx` + `Today.tsx`）：原先只处理 `overview.error`，
   `/api/rebalance` 单独失败时用户无从知道为什么；现按本项目约定带出后端中文原因。
3. **`/api/explain`「适用边界」不再是 Python 字面量**（`app.py::_scope_text`，计划书 §9.2）：
   原为 `str(scope)[:80]` → 界面出现 `{'applies_to': [...]}` 且被截断；

### 7.5 交互动效（2026-09-30 第四批）

用户：「还有一些互动的动态效果，也可以酌情加到里面」。

**原则：动效用来解释状态，不是装饰** —— 每条都要能说出它解决了什么问题，说不出来就不加。

| 动效 | 解决什么 | 实现 |
|---|---|---|
| 卡片**错峰**入场 | 整屏卡片"唰"地同时出现是最廉价的效果；错峰让眼睛按阅读顺序接收 | `main > :nth-child(k)` 依次 0/60/120/180/240/300/360ms |
| 收益曲线**依次绘制** | 两条线同时画完就看不出"谁先偏离" | 本组合 0ms、沪深300 延后 260ms，各 950ms ease-out |
| 建仓进度条**从左侧长出** | 静态满条读不出"已经投了多少" | `.grow-x`（`transform: scaleX` 走合成层，不触发重排） |
| 温度尺**指针滑入** | 指针直接出现，读不出它"落在哪一档" | `.slide-thumb` 从 `left:0` 滑到目标位 |
| **骨架屏**替代「加载中…」 | 一行字没有信息量；骨架给出内容的"形状" | `.skeleton` shimmer；容器 `aria-hidden` + `sr-only` 文案，避免读屏重复播报 |
| 表格行 hover **左侧极光** | 长表格里"跟住一行" | `.row-hover:hover` 左侧渐变 |

⚠️ **两条纪律（都踩过或差点踩）**：
1. `.rise-in` 必须用 **`fill-mode: backwards`** 而不是 `both` ——
   `forwards` 会把 `transform` 永久钉在 keyframe 上，之后任何 hover 变换都会**静默失效**。
2. **卡片不做 hover"抬起"** —— 卡片不是可点元素，抬起会暗示可点击，是误导。
   卡片 hover 只改边框亮度。

**验收（新增探针，8/8 通过）**：动效**不能靠静态截图验收**，改为读**计算样式** ——
错峰延迟实测 `0s / 0.06s / 0.12s / 0.18s / 0.24s`；`animation-name` 分别为
`qfa-rise` / `qfa-grow` / `qfa-slide-thumb` / `qfa-shimmer`；注入 warming 后骨架屏确实出现；
`prefers-reduced-motion: reduce` 下入场动画为 `none`。脚本 `D:\DSH\scratch_hold\_v6_anim.py`。

- `manualChunks` 用**函数**而不是对象形式：对象形式 `{ react: ['react','react-dom'] }`
  实测只分出一个 **0.0KB** 的 `react-*.js`（子路径 `react-dom/client` 没命中），
  React 仍留在 index —— 等于白建一个空文件让浏览器多请求一次。
- **把 Recharts 从首屏剥离**：`CurveChart`（卡片外壳：标题/大数字/图例/脚注）保持同步渲染，
  绘图拆到 `ChartPlot` 懒加载。骨架**高度与真实图完全一致**（只替 210px 绘图区）→ **零布局位移**。
  `lib/chartColors.ts` 单独成文件，否则外壳一 import 色值就把整个 Recharts 拉回首屏 chunk。
- ⚠️ **实话**：本机托管没有网络延迟，所以"整页总字节"几乎没变。拆包在这里的收益是
  **首帧更早**（渲染不再等 695KB 全下完）+ 消掉 Vite 警告 + 依赖 chunk 缓存复用。
  真正的大头见 §9.9。

### 7.10 Bento 栅格（2026-10-01）

**为什么只落在「研究」「设置」两页** —— 先说一个发现：
「今天」页**其实已经是 Bento 了**（结论 / KPI / 曲线 / 持仓+温度，四块的轻重本来就不同），
再套一层栅格没有增量。真正"整页竖着堆一列、宽屏白白空着"的是另外两页：

| 页 | 改前 | 改后（`xl` 起） |
|---|---|---|
| 研究 | 板块、池子各占整行，上下堆 | **板块 5 栏 ｜ 池子 7 栏** 并排（池子是主体） |
| 设置 | 四张卡竖着堆成一条长列 | **2×2**：计划 7 ｜ 画像 5 ／ 模型 7 ｜ 运维 5 |

- `components/Bento.tsx`：`<Bento>`（12 栏容器，**`xl` 起生效**）+ `span(n)`（格子占宽，
  直接当 `Card` 的 `className`，**不额外套容器 div**）。
  断点选 `xl`：`lg` 下内容区只有 ~810px，分栏会把表格压瘦。
- ⚠️ `span()` 必须带 **`min-w-0`** —— 栅格子项默认 `min-width: auto`，宽表格会**撑破**格子
  （而不是出现横向滚动）。与 `App.tsx` 里 `flex-1` 必须配 `min-w-0` 是同一类坑。

**顺带修掉一个潜伏 bug（错峰节奏会断）**：错峰原本写成
`main > *:nth-child(k) { animation-delay: … }` **外加** `main > * > *` 两层选择器 ——
卡片一旦被包进栅格（多一层），**节奏就断了**。改成用**可继承的自定义属性**下发：
`main > :nth-child(k) { --rise-delay: … }`，`.rise-in { animation-delay: var(--rise-delay, 0ms) }`，
嵌套多深都拿得到。
`grow-x` / `slide-thumb` 也改为 `calc(var(--rise-delay) + 120/160ms)` ——
于是"卡片出现 → 条子长出来 → 指针滑入"成为有先后的一条时间线，而不是同时发生。

## 11. 视觉验收判据（把"高品质"变成可判定项，2026-10-04）

### 11.1 背景：一条不可执行的 prompt

用户转述的原始 prompt：

> 「以 Awwwards、Webby Awards、FWA 获奖级网站为品质标准，完成后从排版、留白、视觉层级、色彩、
> 动效、微交互、响应式和原创性上自检并持续优化，直到没有明显可提升之处。」

**它的问题不在"标准高"，而在三处不可执行**：

| 病 | 为什么在本项目里致命 |
|---|---|
| **"直到没有明显可提升之处"** | 无终止条件 + 让执行者自评。agent 永远能找出"还能更好"，于是要么死循环、要么在某一轮**自己宣称完美**——而这份自评不可信 |
| **"以 Awwwards 为品质标准"** | Awwwards 的主流是**叙事型沉浸站**（首屏视觉冲击、动效重）。本产品是**每天看数字的账本**，且用户已明确否定过"数据大屏"风 → 直接把它的视觉语言当验收标准会**与产品定位打架** |
| **"原创性"** | 本质不可判定，且**不能进判据**（会诱导"为不同而不同"） |

**本项目所有改动都有可判定门禁**（pytest 822 项 / 数据契约 24 项 / 前端真机 33 项，全部退出码 0/1）。
这条 prompt 一旦照抄，会引入项目里**第一个"凭感觉宣称完成"的口子**。

### 11.2 改造：保留精神，去掉病

> 视觉标准 = 参考**成熟产品源码**（shadcn-ui / Ghostfolio / 同花顺，§2.1 已做过）而非获奖站审美；

> **完成依据只能是脚本退出码 0**，不能是"我觉得已经很好看了"。

#### 11.4.1 B-0 落地的四条判据修订（2026-10-04，按"先改判据"规则执行）

**修订 1 · 排版「不出现裸值」在本项目无法字面成立 → 改为「阶梯 + 种类上限」**

`@theme` 里**只有** 19 个 `--color-*` + 4 个 `--radius-*` + 2 个 `--font-*`，
**没有任何 `--text-*` 字号 token**。Tailwind v4 的 `text-[13px]` 并不是"绕过 token"，
而是这个项目里**唯一**的字号表达方式。因此原判据写死会要求先造一套字号 token 体系
（属产品级设计变更，不在 B-0 范围）。折中为两条可判定项：

1. 字号值必须落在 **0.5px 阶梯**（离散化）—— 抓 `13.7px` / `10.2px` 这类随手拟的值；
2. 全站字号**种类 ≤16 档**（现状 14 档）—— 留 2 档余量做"定型"，超了就说明在扩散。

**修订 2 · 留白「间距 ∈ 4 的倍数」→ 收紧为「2px 网格」**

原文的"4 的倍数"会把 Tailwind 的**半档**全判红：`-0.5`(2px) / `-1.5`(6px) / `-2.5`(10px) / `-3.5`(14px)。
实测现状 218 处间距里 **95 处**用了半档，且都是有意的细分节奏（卡内 `p-3.5`、标题 `mb-1.5`），
不是原文要抓的"13px/17px 这类随机间距"。真正的问题是**离开 2px 网格**的值。
故判据定为「间距 px 值必须是 2 的倍数」，原文要抓的 13/17 依然会被抓到（13 % 2 = 1）。

> ⚠️ 这条判据**修对了一个真漏洞**：最初只扫 Tailwind 档位写法（`p-3` / `gap-1.5`），
> 负对照（注入 `space-y-[13px]`）证明**任意值写法会漏网** —— 而"随手写个 `-[13px]`"
> 恰恰是散落间距的**主要**形态。现已同时扫 `-N` 与 `-[Npx]` 两种写法，
> 并据此在 `SourceTag.tsx` 抓到 2 处真实违规（`py-[3px]` → `py-1`）。

**修订 3 · 层级「同页字号种类 ≤4 档」→ 改为「h 标签单调 + 头层>卡标题」，种类数降级为诊断**

原判据按**每个 `.tsx` 文件**量字号种类，现状最坏 6 档（`routes/Settings.tsx`：11/11.5/12/12.5/13/16）。
但**量错了对象**：4 档讲的是"信息层级"（页标题 → 卡标题 → 正文 → 注脚），
而 11/11.5/12/12.5 全落在"正文/注脚"同一层里做微调 —— 这不是层级扁平化，
是一张表里**三种列宽共用最小可读尺寸档**的细分。按文件扫会把正常表格判成"层级失控"。

拆成两条**指向真问题**的可判定项：

1. `h1..h6` 字号必须**严格递减**（防"卡标题比页标题还大"的倒挂）；
2. 页面头层（`h1`）字号 **>** 卡标题（`Card` 的 `h2`）字号。

"每页字号种类"改为**诊断输出**（打印在 detail 里，不参与成败）—— 保留可见性，不制造假红。

**修订 4 · 追加第八维「数字等宽」**

原七维里没有这一项，但它是本项目**最有业务含义**的一条：金额/涨跌幅/份额在竖排时必须等宽，
否则数字会跳动。判据 = "货币/百分比/份额的格式化值（`fmtMoney`/`fmtPct`/`toFixed`）必须坐在带
`.num` 或 `.mono` 的容器里"。B-0 据此修了 3 处真实违规（`KpiRow` 基数、`Settings` 目标占比、`CurveChart` 未入仓金额）。

> ⚠️ 该判据是**正则近似**（非 AST）：只抓单行内"格式化值直接坐落在无 `num`/`mono` 的元素里"。
> 多行 JSX / 三元分支会漏。**故意为之**：漏判（假绿）比误判（假红）可接受，
> 误判会让人把判据当噪音直接关掉。

#### 11.4.2 判据可跑性

静态四项（排版/留白/层级/数字等宽）**不依赖服务与 Playwright**：
`python scripts/verify_frontend.py --static-only` 可单独跑（退出码 0/1）。
默认模式下服务不可达时，动态项降级为 `[SKIP]`（**不计入 RESULTS**，避免 `ok == len(RESULTS)` 恒真骗退出码），
静态项照跑。CI / 提交前自查用 `--static-only` 即可，改前端布局时才需要完整跑一遍。

⚠️⚠️ **探针必须绕过环境代理**（2026-10-05 踩到，属"假绿"级坑）：
本机沙箱导出了 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:<port>`（WorkBuddy 自己的代理），
而 `urllib.request.urlopen` **默认会读这两个变量** —— 于是连 `http://localhost:5020/v2`
都被转发到代理上、返回 502 → 探针判"服务不可达" → **动态 33 项被静默 `[SKIP]`，汇总只显示 7/7**。
它比假红危险得多：看起来"跑过了"。修法 = 显式用空 ProxyHandler：

```python
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

**Playwright 不走这套环境变量**（它有自己的 proxy 配置），所以只有 `probe_server` 这一处会中招。
**自查办法**：完整跑一次应得 **40/40**；若只有 7/7 且带 `[SKIP]` 行，先查服务与代理。

⚠️ **起服务要用受管的常驻后台方式**（2026-10-05 踩到）：`(python src/main.py web &)` 这种
子 shell 分离写法，进程会在**该次工具调用结束时被清理**（实测：curl 返回 200 后 30 秒即消失），
于是紧随其后的 `verify_frontend.py` 又变成"不可达"。本机可用 run-in-background 方式常驻。

### 12.1 一页备忘：几个必须记住的坑

| 坑 | 内容 |
|---|---|
| **Python 解释器** | 测试/Playwright 都用**系统** Python（`...\Programs\Python\Python313\python.exe`）；托管那个没有 pytest |
| **`verify_frontend.py` 前置** | 必须 `precompute`（本轮实测 131.9s，快照 TTL 6h），且确认 `funds_board_8_300` 在快照里 |
| **落盘快照缓存** | `/api/overview\|rebalance\|explain` 有 `analysis_snapshot` → 改后端后页面仍读旧载荷，**必须 `?fresh=1`** |
| **视觉验收** | 必须用**视口截图**（`background-attachment: fixed` 在 `full_page=True` 下只渲染顶部一屏） |
| **动效验收** | 读**计算样式**（`animationName/Delay`）+ `reduced_motion="reduce"` 下必须为 `none` |
| **`.rise-in`** | `fill-mode` 必须是 `backwards`（`both` 会钉死 transform → hover 静默失效） |
| **sandbox** | 缺 coreutils；inline 命令含 "power"+"shell" 字样被拦 → 写成 .py 再跑 |
| **后台任务** | 不跨会话存活 → 长任务必须可续跑 |
| **审计文档** | 新章节**一律追加到文末**（插中间会打乱编号） |
