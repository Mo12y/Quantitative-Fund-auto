## 0. 结论摘要

**可以做一个真正站得住的基金推荐 —— 但它的形态是「同类百分位 + 用户约束」，不是「打分排名」。**

三句话：

1. **可做**：把毕设的「市场参照系」范式迁过来，用**同类基金的群体分布**替代现在那套拍脑袋阈值。
2. **但只能分类型做，且当前只有 5 个权益类型够样本** —— 债基与指数型的深历史样本不足（`【实测】`见 §3）。
3. **最关键的一条**：必须先解决**数据代表性**。当前 84.35% 的净值覆盖率是假象，真正有 3 年以上历史的只有 576 只（2.1%）。

> ⚠️ **skill 规则 1（数据源验证前置）+ 规则 7（地基验证）**：地基是「净值数据能不能代表市场」，
> 不是「算法好不好」。地基不成立，上面全是垃圾。

## 1.（b）毕设「参照系」→ 基金：迁移对照

### 1.1 毕设的参照系由 4 个组件构成（`【实测】`已读源码）

| # | 组件 | 毕设实现 | 作用 |
|---|---|---|---|
| 1 | **核心算法 SSOT** | `analysis/danmaku_metrics.py`（密度曲线 + 8 维指标） | pipeline 与 analysis **都 import 它，禁止内联复制** |
| 2 | **参照系构造** | 群体分布（中位 + IQR + P10/P90）→ 单个体表达为**百分位** | 把「绝对分数」换成「在群体中的位置」 |
| 3 | **阈值分位数化** | `analysis/benchmark_threshold.py` | 算全体两两相似度分布 → P75/P90 作阈值；**并报告「旧拍脑袋阈值在分布中的位置」** |
| 4 | **参照系稳定性验证** | `analysis/g02_stability.py` | 跨批比中位数漂移（<15%）+ Mann-Whitney（p>0.05）；不稳定就如实报告 |

### 1.2 逐项迁移

| 毕设 | 基金项目对应 | 迁移难度 |
|---|---|---|
| 视频（bvid） | 基金（fund_code） | 直接对应 |
| 弹幕时间戳序列 | **净值时间序列** | 直接对应 |
| 101 点密度曲线 | **日收益率序列 / 滚动指标序列** | 直接对应 |
| 8 维节奏指标 | **基金指标**：年化收益、年化波动、最大回撤、夏普、Calmar、动量、规模、费率、成立年限 | 已有（`fund_scorer` 的 6 维 + `vol_predictor` 的 15 特征） |
| **市场参照系**（热榜视频群体分布） | **同类基金群体分布** | ⚠️ **关键：必须先定「同类」**（见 §3） |
| 对标：市场百分位 + Top3 相似 | 基金：同类百分位 + Top3 相似基金 | 直接对应，且相似基金本身有用（替代品发现） |
| 拍脑袋阈值 0.7 → 全库 P75 | 拍脑袋 `max_drawdown_1y: 35` → **同类 P75** | ⭐ **本次迁移的核心价值** |
| 对照组（`ctrl_` 前缀独立处理） | 指数基金 vs 主动基金（基准不同，不可同池） | 直接对应，且必要 |
| **时间稳定性验证**（g02） | **参照系逐月漂移检验** | ⭐ **基金项目完全缺失，最该补** |

### 1.3 毕设 `benchmark_threshold.py` 的方法（可直接照搬骨架）

```python
# 毕设原文逻辑（55 行）：
X = 全库 × 8维指标
mins, maxs = X.min(axis=0), X.max(axis=0)          # 逐维
Xn = (X - mins) / span                              # 标准化到 [0,1]
sims = cosine_similarity(Xn)                        # 两两相似度
pairwise = sims[np.triu_indices(n, k=1)]            # 上三角，排除自身
for p in [1,5,10,25,50,75,90,95,99]:                # 打印全部分位数
    print(f'P{p}: {np.percentile(pairwise, p)}')
p75, p90 = np.percentile(pairwise, [75, 90])
print(f'高置信度阈值 = P75（{p75}）—— 替代拍脑袋的 0.7')
print(f'当前 0.7 阈值在分布的 P{np.mean(pairwise <= 0.7)*100:.0f} 位置')   # ★ 这句最有价值
```

**四个可迁移的细节**：

1. **逐维标准化到 [0,1]**（不是 z-score）—— 与线上服务用同一口径，否则参照系与展示不一致
2. **排除自身的上三角** —— 否则对角线上的 1.0 会把分布整体抬高
3. **打印完整分位数表**，不只取 P75/P90 —— 便于事后验证
4. **⭐ 报告「旧阈值在分布中的位置」** —— 这一句是自我校准的关键。
   基金项目照做就能回答：`max_drawdown_1y: 35` 这个常数在同类分布里到底位于第几分位？

> `【推测】`按经验，基金「近1年最大回撤 35%」在偏股混合里大约位于 P60~P75 区间——
> 即它并不严格，只是中等偏松。**证伪条件**：跑一次 §4.1 的校准脚本即可确认。

### 2.2 参照系范式替换后

```

    ↓

```

且**阈值本身会被数据重新校准**——市场整体波动变大时，P25 自动跟着变，不需要人工调参。

## 3.（c）参照系的分类型方案（附实测数据）

### 3.1 为什么必须分类型

`【实测】`当前同池排序的后果（引自本轮审计）：

| 证据 | 数值 |
|---|---|
| `current_picks` Top12 中债基数量 | **9 只** |
| 债基在候选池中的占比 | 44% |
| 原因 | `dd_score = (50 - max_dd)/50*100` —— 债基回撤 2~5% 得 90+ 分，权益回撤 30~50% 得 0~40 分 |

→ **30% 的权重是债基的免费分。** 债基与权益的动量、回撤区间**根本不可比**，同池排序必然失真。

### 3.2 ⚠️ 决定性约束：深历史样本只够 5 个类型

`【实测】`命令：见 §8.1。**净值日期分布揭示「84% 覆盖率」是假象**：

```
2026年   23,421 只   ← 其中 23,415 只只有 2026-09 一个月（一次性快照）
2025年      590 只
2024年      586 只
2023年      581 只
...
2013年       32 只
```

| 指标 | 数值 |
|---|---|
| 全市场（有类型） | 27,753 只 |
| 有净值 | 23,409 只（84.35%） |
| **净值 ≥3 年（756 天）** | **576 只（2.07%）** |
| 净值 ≥1 年（252 天） | 590 只 |

**放宽到 1 年几乎不变（590 vs 576）** —— 说明深历史那批本来就有多年数据，其余只有一个月。

### 3.3 按类型的深历史样本（`【实测】`）

| 类型 | 深历史(≥3年) | 建议 |
|---|---|---|
| 混合型-偏股 | **192** | ✅ 全量参照系（可用 P10/P90） |
| 混合型-灵活配置 | **129** | ✅ 全量参照系 |
| 股票型-普通 | **95** | ⚠️ 中位 + IQR，**不用极分位** |
| 股票型-标准指数 | **65** | ⚠️ 中位 + IQR |
| 股票型-增强指数 | **31** | ⚠️ 中位 + IQR，结论标「样本受限」 |
| 债券型-普通债券 | 23 | ❌ 不足 |
| 债券型-长期纯债 | 15 | ❌ 不足 |
| **指数型-股票** | **7** | ❌ **全市场 5588 只，深历史仅 7 只** |
| 混合型-股债平衡 / 债券型-中短债 / 其余 | 2~4 | ❌ 不足 |

### 3.4 由此得出的分类型规则（`【推测】`，依据 skill 规则 8「样本量驱动方法」）

skill 规则 8 的判据是「几十~几百条 → 相关/线性回归/规则；几万+ → 复杂模型」。
迁移到分位数估计：

| 样本量 n | 允许的统计量 | 理由 |
|---|---|---|
| **n ≥ 150** | 中位 + IQR + P10/P90 | P90 处约 15 个样本，分位估计稳定 |
| **100 ≤ n < 150** | 中位 + IQR + P25/P75 | P90 处样本过少 |
| **30 ≤ n < 100** | **仅中位 + IQR** | 极分位不可靠；UI 必须标「样本受限」 |
| **n < 30** | **不建参照系** | 退化为「与同类中位数比较」，并显式声明 |

> **证伪条件**：若用 bootstrap 重采样估计 P90 的 95% 置信区间宽度 > 该指标 IQR 的 50%，
> 则即使 n≥150 也应降级为 P25/P75。

### 3.5 类型体系建议（不要用 44 种，聚合为 6 组）

`【实测】`全库有 **44 种** `fund_type`。直接按它建参照系会碎成无法使用的碎片。建议聚合：

| 聚合组 | 包含的原始类型 | 深历史样本 |
|---|---|---|
| **A 偏股混合** | 混合型-偏股 | 192 |
| **B 灵活配置** | 混合型-灵活配置、混合型-灵活、混合型-平衡 | 133 |
| **C 主动股票** | 股票型、股票型-普通 | 97 |
| **D 指数股票** | 股票型-标准指数、股票型-增强指数、指数型-股票 | 103 |
| **E 债券** | 债券型-*（全部） | 45 ❌ 暂不足 |
| **F QDII / 其他** | QDII-*、FOF-*、商品、货币型 | <30 ❌ 暂不足 |

→ **当前可建参照系：A / B / C / D 四组**（合计 525 只）。
→ **E / F 两组待补采集**。

> **为什么把「指数型-股票」并进 D 而不是单独建**：它全市场 5588 只但深历史仅 7 只
> （`【实测】`），单独建毫无意义；而「股票型-标准指数 65 + 增强指数 31」与之同属被动/半被动，
> 合并后 103 只可勉强建组。**但这引入了一个偏差**：主动指数增强与纯被动指数的风险特征不同，
> 合并会稀释参照系的纯度。**建议在 UI 上标注「D 组为合并口径」。**

## 4.（a）完整设计方案

### 4.1 第 0 步：阈值校准脚本（先做这个，不改业务代码）

**照搬 `benchmark_threshold.py` 的形态，产出「旧阈值在同类分布中的位置」报告。**

```
scripts/calibrate_thresholds.py
  输入：深历史基金（≥3年）× 各指标
  分组：按 §3.5 的 A/B/C/D 组
  输出（每指标每类型）：
     P1 / P5 / P10 / P25 / P50 / P75 / P90 / P95 / P99
     均值 / 标准差
     ★ 现有常数阈值位于分布的 P?? 位置
     ★ 该阈值在该类型下的实际通过率
```

**为什么先做这个**：它是纯只读的分析脚本，
- 不改任何业务逻辑 → 无风险
- 立刻回答「现在的阈值到底严不严」
- 产出直接喂给 §4.2 的参照系表

> skill 规则 12（实测对比）：**能跑就先跑，别用嘴论证。** 这一步就是「先跑」。

### 4.2 参照系表（新增一张表，不侵入现有逻辑）

```sql
CREATE TABLE fund_benchmark (
    fund_type_group  TEXT,      -- A/B/C/D
    metric           TEXT,      -- annual_return / max_drawdown / sharpe / ...
    as_of            TEXT,      -- 快照日期（参照系是时点量，必须带日期）
    n                INTEGER,   -- 样本量
    p10 REAL, p25 REAL, p50 REAL, p75 REAL, p90 REAL,
    mean REAL, std REAL,
    quality_level    TEXT,      -- full / median_iqr_only / insufficient
    computed_at      TEXT,
    PRIMARY KEY (fund_type_group, metric, as_of)
);
```

**关键设计**：参照系是**时点量**（`as_of`），不是常数。
→ 这直接支撑 §4.5 的稳定性验证。

### 4.3 评分改为「同类百分位」

```
旧：score = f(绝对指标值)              → 债基系统性胜出
新：percentile = 该基金在同类分布中的位置  → 各类型各在自己分布里比
```

**输出形态**（这才叫「推荐」，不只是「排名」）：

```
014143 银河创新成长混合C        组别：A 偏股混合（同类 192 只）
  年化收益   18.2%   同类 P72  ↑ 优于 72% 的同类
  最大回撤   28.4%   同类 P45  → 中位附近
  夏普        0.82   同类 P68  ↑
  年化波动   24.1%   同类 P55  →
  ⚠️ 未评估：规模（数据缺失）· 费率（数据缺失）· 经理年限（数据缺失）
  ⚠️ 样本受限：本组 192 只，P10/P90 分位估计的置信区间较宽
```

> ⭐ **「未评估」那一行是设计的核心。** 按 skill 规则 14 与项目既有约定
> （温度计的 `degraded_dimensions`、API 的 `degraded`），
> **缺失必须声明，不得静默填中性值**。

### 4.4 用户约束层（B 层，本次只留接口不实现）

```
第 1 层  客观参照系      ← 本方案范围（纯客观、零用户依赖）
第 2 层  用户约束        ← user_profile + user_holdings + 持仓重叠度
第 3 层  推荐 = 第1层 ∩ 第2层约束
```

**架构纪律**：第 1 层**不得引用任何用户信息**。
这样 A（自用）→ B（个性化）→ C（上线）是叠加，不是重写。

⚠️ **当前违反此纪律的地方**：`investment_plan.py` 把计划写死在代码常量里
（`TOTAL_CAPITAL = 1000.0`、`CASH_RESERVE = 280.0`、基金清单硬编码）。
这是 C 的最大阻塞项。

### 4.5 参照系稳定性验证（毕设 g02 的迁移，基金项目完全缺失）

```
scripts/verify_benchmark_stability.py
  对每个类型组、每个指标：
    逐月重算参照系 → 比较中位数漂移
    判定：漂移 <15% 且 Mann-Whitney p>0.05 → 时间稳定，可用
          漂移 ≥15% 或 p<0.05            → 该维度随市场演化，必须报告波动范围
```

**为什么必需**：如果某指标的参照系逐月漂移剧烈，
那么「同类 P72」这个说法**本身不稳定** —— 上个月 P72 的基金这个月可能变 P45。
用它做推荐 = 拿一把会伸缩的尺子量东西。

> skill 规则 11（地基再验证）：「已确认结论」会免疫于质疑。
> 参照系一旦建好就会被当成地基，**必须定期重验**。

### 4.6 推荐的可解释性（L2，这是「排名」与「推荐」的分界线）

每个推荐必须能回答三问：

1. **为什么入选** —— 哪些维度在同类中靠前（附百分位与样本量）
2. **为什么落选** —— 被排除的候选给同样明细（当前是完全不透明）
3. **缺什么没评估** —— §4.3 的「未评估」行

### 4.7 实施顺序

| 序 | 事项 | 依赖 | 风险 |
|---|---|---|---|
| 0 | **补采集深历史净值**（目标：每类型 ≥150 只） | 出网 | 低（只读采集） |
| 1 | §4.1 阈值校准脚本（只读） | 0 | **零风险** |
| 2 | §4.2 参照系表 + 计算脚本 | 1 | 低（新增表） |
| 3 | §4.3 评分改为同类百分位 | 2 | 中（改推荐输出） |
| 4 | §4.5 稳定性验证 | 2 | 低（只读） |
| 5 | §4.4 用户约束层（B） | 3 | 中 |
| 6 | §4.6 可解释性 UI | 3 | 低 |

**先做 0 和 1**：0 是数据地基，1 是零风险且立刻有产出。

## 5. 用 first-principles-review（v2.7）做的对抗式审查

> 按 skill 的「输出格式」节执行。**这是本文档最该认真看的部分。**

### 5.1 第一性原理

**拆解**：推荐系统的物理含义是「在可选集中，按某准则排序并给出理由」。
- 输入：基金的历史序列 + 用户约束
- 输出：有序清单 + 每条的理由
- **删除测试**：删掉「用户约束」还能回答「买什么」吗？
  → **能，但答案对所有人一样**。所以用户约束是 B/C 的必需、A 的可选。**保留为独立层**，不混入评分。

**因果链**：
- 特征 → 标签方向对吗？→ 本项目**不预测**，只做同期描述与比较，**无标签**，因此无「标签泄漏」风险。
- 有隐藏混杂变量吗？→ **有，且严重**：市场环境。牛市里所有权益基金收益都高，
  所以「同类百分位」在牛市里也是相对的 —— **这是分位数化的优点**（自动去除市场 beta）。
- 「相关性」被包装成「因果性」吗？→ ⚠️ **风险点**：不能声称「高夏普 → 未来收益高」。
  参照系只是**描述性**的。措辞必须是「该基金历史回撤控制优于同类 75%」，
  **不是**「该基金会继续表现好」。

### 5.2 对抗式审查（5 攻击）

| 攻击 | 内容 | 结论 |
|---|---|---|
| **假设** | 最核心假设：「同类基金可比」。若不成立（如 A 组里混入打新基金、定开基金），参照系全塌。 | ⚠️ **真实风险**。需在分组时排除：定开/持有期基金、打新基金、转型期基金 |
| **数据** | 深历史只有 576 只（2.1%），这 576 只会不会系统性偏向「存活久的老基金」？ | ⚠️ **是**。这是**幸存者偏差**——能活 3 年以上的基金本身就是筛选结果。参照系会偏乐观 |
| **替代** | 更简单的方法能达同样效果吗？ | ✅ **有**：只做「与同类中位数比较」+ 明示「未评估维度」，不建完整分位数。如果 §4.1 显示现有阈值其实还行，可能不需要全套 |
| **规模** | 能做完吗？ | ✅ 能。§4.1/4.2/4.5 都是只读脚本，一天可出 |
| **叙事** | 一句话讲清解决什么问题？ | 「让基金比较有同类基准，而不是和拍脑袋常数比」 |

### 5.3 奥卡姆剃刀

1. 两特征 r>0.8 → 留物理含义清晰的
   → `【口径】`已被上一轮做过：`vol_predictor` 曾因 `peak_intensity` 与 `cv` 相关 0.945 而替换。
   **基金侧同样要做**：年化收益/夏普/Calmar 高度相关，参照系里不必三个都留。
2. 一个模块能被一条 SQL 替代 → 它不该是模块
   → **§4.2 的参照系计算确实可以是一条 SQL**（`GROUP BY type, metric` + 分位函数）。
   **建议：先写成脚本，不要急着建模块。**
3. 实验与核心假设无关 → 砍
4. 面板信息能从别处推导 → 砍

## 6. 合规边界（C 上线时必读）

| 场景 | 法律性质 | 要求 |
|---|---|---|
| A 自用 | 个人研究 | 无 |
| B 自用 + 个性化 | 个人研究 | 无 |
| **C 对外提供** | ⚠️ **可能构成基金投资顾问业务**（需牌照） | 见下 |

**C 的最低安全边界**：

1. **措辞**：不用「建议买入」「推荐」。改为「客观数据展示」「同类对比」「持仓结构分析」
2. **不做择时建议**：「当前应加仓至 X%」这类输出风险最高
3. **显式免责**：页脚常驻「本系统仅提供公开数据整理与统计对比，不构成投资建议」
4. **谨慎收集真实持仓**：这是最敏感数据；如收集须明确告知用途与存储方式
5. **不承诺收益**：任何「历史年化 X%」都要附「不代表未来表现」
6. **账号体系**：参考毕设做法 —— 不开放注册，管理员建号；密码 hash；`.env` 不入库

> **毕设的经验直接适用**：它推荐「视频节奏」没有合规问题；
> 推荐「买哪只基金」性质完全不同。**这是本方案最大的非技术风险。**
