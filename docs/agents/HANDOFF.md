#### 三、注意事项（本轮新增的坑）

1. ★ **接物化表（`fund_metrics`）有两条硬约束，别绕开**：
   ① **`risk_free_rate` 与 SSOT 默认不一致时必须在入口拒用**物化值
     （否则同一只基金的夏普会随调用方而变）；
   ② **SQLite 不存 NaN → 物化值是 `None`，必须先归一成 `nan`**
     （`np.isfinite(None)` 会抛 `TypeError`）。
2. ★ **别用 `fund_metrics_store.load_or_compute()` 去接 `fund_scorer`** ——
   它会对"物化缺失"的基金**再批量读一遍 NAV**，而 `screen_funds` 刚刚已经读过 → **双倍 IO**。
   用 `load()`（**纯读**），缺失者交给 `_score_series` 用已有序列算一次。
3. ★ **冷启动时 Web 会非常慢，别同时发多个重请求**：`funds` / `rebalance` / `__dash__` /
   `funds_board_*` 各是一次**全市场冷算（实测 68~140 s）**，快照 TTL 只有 **6 h**。
   `SLOT_WAIT=30s` 超时后后来者会"**接管计算**"→ 同一份活被算两遍 → 服务器可十几分钟不响应
   （本轮因此把「今天」页的曲线图都拖到 20 s 超时）。**要跑前端验收就先把快照补齐再起服务**。
4. ⚠️ **改含反引号的文档/字符串，绝对不要用 shell 传**（本项目已踩过两次）——
   本轮我用 `python -c "...`path`..."` 归档 HANDOFF，反引号被 shell 当命令执行，
   把指针行吃成 `→ 。`，还在仓库根**误建了 7 个垃圾文件**（`→` / `⚠️` / `门禁` …，已删除）。
