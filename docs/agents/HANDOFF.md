#### 三、注意事项（坑）

1. ★★ **本文件的写方法必须用 `db._commit()`，不要 `self.conn.commit()`**
   —— 直接 commit 会把外层 `immediate()` 提前提交，原子性就没了。
   纪律由 `tests/test_db_immediate_atomicity.py` 钉住（**负对照会红**：把 `_commit`
   打回旧行为，那两条回滚断言立刻失败）。新增写方法时照抄现有写法即可。
2. ★ **`precompute` 预热的是 `funds_board_20_300`，而前端「研究」页请求的是
   `funds_board_8_300`**（`Research.tsx` → `fundsBoard(8, 300)`）。
   **只跑 `precompute` 的话研究页会永远 warming**（代码注释里踩过一次，本轮又靠脚本补齐才跑绿）。
   跑验收前建议用一个独立进程把两个 key 都 `_cached_get` 一遍再起服务。
3. ★★ **别把实现到一半的改动留在工作树里** —— 本轮接手的三个改动（A3 / B / E2）
   全是上一轮"已实现未提交"，且**没有任何交接块提到它们还挂着**。
   铁律 8「大操作即记录」的反面就是这种状态：**代码存在、测试通过、但没人知道它还没提交**。
   做完一项就 commit，哪怕消息短。
4. ★ **冷缓存 + 并发重请求会把 Web 拖死**（本轮复现）：`funds`/`rebalance`/`__dash__`/
   `funds_board_*` 各是一次全市场冷算（**本轮实测 41~74 秒/次**）；
   `SLOT_WAIT=30s` 超时后后来者会**接管计算** → 同一份活算两遍 → 服务器十几分钟不响应。
   **先预热、再起服务、再验收**，别边跑验收边点页面。
5. ⚠️ **改含反引号的文档/字符串不要走 shell**（本项目已踩两次）——
   本轮归档交接块改用**先写脚本文件再执行**，避开反引号被 shell 当命令执行。
6. 其余坑见归档（`docs/_archive/`）与 `AGENTS.md` §五。
