# 基金推荐系统：机器学习可行性研究

> 撰写：2026-09-18　｜　配套：`docs/factor_test_report.md`、`docs/vol_prediction_report.md`、`docs/vol_model_comparison_report.md`
> 结论一句话：**可以做，但必须做成「风险刻画 + 排序 + 排除差基金」的模块，而不是「预测涨跌的荐基引擎」。**

---

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 技术上能不能做？ | **能**。数据量与工具链够用，且本仓库已有可复用的先例（`vol_predictor.py` 的 walk-forward 骨架） |
| 该不该做成"选基神器"？ | **不该**。本项目的因子天花板测试与外部复现研究，都指向"收益方向不可预测" |
| 真正有价值的方向是什么？ | ① **风险刻画**（波动/回撤/风格漂移）② **排序与排除**（把明显差的基金剔掉）③ **决策一致性校验**（防止手工权重拍脑袋） |
| 第一步该做什么？ | 零新依赖的 **Ridge/rank 组合 + purged walk-forward 评估台**，先与现有 `quality_score` 基线对打 |
| 最大风险 | 幸存者偏差 + 重叠标签泄露 + "统计显著但无实用价值"。三者本项目都已踩过或已披露 |
| 需要的决策 | 是否允许引入**可选**依赖（scikit-learn）？是否先补**已清盘基金**数据？ |

## 1. 我们手上有什么（实测数据规模）

| 数据 | 实测值 | 对 ML 的意义 |
|---|---|---|
| `fund_info` | 27,852 条（**仅 588 只有净值**） | 结构特征（类型/规模/费率/申购状态）覆盖有限 |
| `fund_nav` | **1,220,179 行 / 588 只**，2013-03-08 ~ 2026-09-15 | 主特征来源；585 只 ≥500 个交易日 |
| `index_daily` | 15,189 行 / **仅 3 个指数** | 市场状态特征偏薄（基准只有 3 条序列） |
| `index_valuation` | 3 行 | PE 分位在采集时留空，`vol_predictor` 用扩展窗口就地补算 |
| 最长历史 | 000016，3,266 个交易日 | 覆盖多轮牛熊，但个股基金普遍不足 |

### 1.1 可构造的特征（现有数据即可，零新增数据源）

- **NAV 派生**：动量（1/3/6/12M）、年化波动、最大回撤、下行波动、偏度/峰度、自相关、Sharpe/Sortino/Calmar、正收益月占比
- **分红行为**（本项目独有且被低估的信号）：`acc_nav / unit_nav − 1` 的累计背离 = **分红频率与幅度**。批次 1-3 已证明 244/587 只基金分过红，这是真实可计算的"分意愿"特征
- **结构**：类型桶（批次 4.4 的 `type_bucket`）、规模、管理费+托管费、成立年限、申购状态
- **市场状态**：市场温度、指数动量、`index_daily.pe_percentile`（扩展窗口补算）

### 1.2 缺什么（决定了能力上限）

| 缺失 | 影响 |
|---|---|
| **已清盘/合并基金** | 幸存者偏差 → 任何"荐基"结论被系统性高估（`factor_test`/`vol_report` 均已披露） |
| 持仓穿透（重仓股/行业暴露） | 无法做风格归因、无法识别风格漂移——而外部研究里"持股特征"恰恰增量很小，故优先级不高 |
| 基金经理变更 / 机构占比 / 换手率 | 文献中的次要特征，缺失可接受 |
| 资金流（申赎） | Kaniel et al. 认为**最重要**的两个特征之一是 fund flow —— 我们**完全没有** |

> 外部研究（Kaniel et al. 2023, JFE）指出：**fund flow 与 fund momentum** 是最重要的两个预测因子，而**持股特征几乎没有增量**。
> 我们恰好有 momentum（NAV 可算）、没有 flow（需扩展数据源，见 `docs/数据源扩展计划书.md`）。

## 2. 机器学习的真实难度（先例数据说话）

### 2.1 本项目自己的两次实证——都在说"别高估"

| 报告 | 尝试 | 结果 |
|---|---|---|
| `factor_test_report.md` | 5 个行业轮动因子（动量1/3/6M、回调、低拥挤度），141 个月 | **全部未通过** Bonferroni 校正；IC 仅 0.003~0.027，ICIR < 0.09。结论：**未发现可被利用的信号**，建议系统转向"资产配置+定投纪律+风控" |
| `vol_prediction_report.md` | HAR-RV / XGBoost 预测下月波动 | HAR-RV **没跑过** EWMA（IC 0.8115 vs 0.8121）；XGBoost 更差（0.8010） |
| `vol_model_comparison_report.md` | Ridge / RF / GB / NN vs EWMA | 最强 ML = Ridge，IC 0.8157 vs EWMA 0.8121 → **+0.0036**，排列检验显著但"**统计显著 ≠ 实用价值**，排序结论几乎不变，却要多维护一个模型" |

**读法**：波动率（信噪比高）都只能提升 0.4%，收益率（信噪比低一个量级）不可能更好。

### 2.2 外部证据：连"成功案例"都被推翻了

- Kaniel et al. (2023, JFE) 用神经网络对 1980-2019 美国主动权益基金预测，报告 top/bottom 十分位年化差 191%。**这篇是"ML 选基可行"的主要支柱。**
- 但 2025 年的独立复现研究（"Does machine learning really help to select mutual funds with positive alpha?"）发现：**原结果源自一处前视偏差编码错误**（构建组合收益时用了下一月而非当月的收益更新权重），并存在幸存者偏差。**修正后，超额收益完全消失**，长期只做多（long-only）无法获得统计显著的正超额。
- 复现研究的一致结论：**ML 的价值主要在"稳定地避开差基金"**（bottom decile 年化 −2%~−3%，显著），而 long-short 的超额（3.0~3.05%/年）**几乎全部来自空头腿——散户不可投资**。
- 另一个可复用的经验：**12 个月预测期上，OLS / Elastic Net 等简单线性模型与复杂 ML 打平**；复杂模型只在 36 个月期上露出优势。

### 2.3 结构性约束（本项目专属）

1. **横截面只有 588 只**，且重叠窗口让"有效独立期"≈ 100 个月量级 → 可支撑的**有效自由度只有个位数到十几个**。这正是 `vol_predictor` 把特征从 30 砍到 16、并最终选用 3 特征 HAR-RV 的原因。
2. **铁律 4 禁止新增运行时依赖**（`requirements.txt` 现无 sklearn/scipy/xgboost 主力位；`vol_predictor` 是**独立可选模块**范式）。
3. **资金规模极小**（定投 ¥10/期）+ C 类份额 → 高换手策略的交易成本会吃掉任何微弱 alpha。
4. **一次错误的前视泄露就能制造出"超额"**——本项目已经吃过 `daily_return` 不可靠、PE 分位留空、基准类型恒为 True 的三个亏。

## 3. 建议方案：三层，先做 L1

### L1 —— 零新依赖（numpy 即可），把"手工权重"换成"数据驱动 + 可检验"

这是**唯一**建议现在做的：

| 项 | 设计 |
|---|---|
| 标签 | 不是绝对收益，而是**同类桶内下期（1/3 月）风险调整收益的分位**（对回撤/波动做调整），或直接预测"是否落入同类后 30%" |
| 特征 | §1.1 清单，控制在 **≤12 个**（自由度约束） |
| 模型 | ① 现有 `quality_score`（**基线，必须对打**）② 等权 rank 组合 ③ **Ridge 闭式解**（numpy 十行代码，`X'X + λI` 直接解） |
| 验证 | **purged + embargo walk-forward**：训练窗口到 t 为止，留出标签重叠期（≥3 月）不参与训练；禁止随机划分（`vol_predictor` 已立此规矩） |
| 指标 | IC(Spearman) / ICIR / Top-K 组合 OOS 超额 / DM 检验 / 与基线并列同窗口 |
| 产出 | `docs/recsys_ml_report.md`：**若 L1 不能显著超过 `quality_score`，如实报告并停止**（沿用 `factor_test` 的先例） |

**L1 的真实收益不是"更高的收益"，而是**：把 `config/settings.yaml` 里那 6 个手工权重（0.25/0.20/0.15/0.15/0.10/0.15）从"拍脑袋"变成"可估计、可检验、可回测守住"的东西。这是**工程收益**，不是 alpha。

### L2 —— 可选依赖（`requirements-ml.txt`：scikit-learn），仅在 L1 通过后

- 模型：`HistGradientBoostingRegressor`（或 `LambdaMART` 排序目标）
- 目标改为**排序**而非回归（learning-to-rank 与"推荐"语义一致）
- 特征可扩到 20-30 个（GBDT 对共线性不敏感，但仍需 purged CV）
- **必须**：非线性模型与 L1 线性模型同窗口对打；若增量 < IC 0.01 量级，按 `vol_model_comparison` 的判词——不值得多维护一个模型
- 定位：**独立模块、失败可降级**（照抄 `vol_predictor.py` 的范式：独立文件、可选依赖、`--max-funds` 限流、结果落 `docs/`）

### L3 —— 深度学习：**明确不建议现在做**

- 样本量：横截面 588、独立期 ~100 → 训练一个 Transformer/LSTM 必然过拟合；文献里能跑通的是 24 万亿美元、上万只基金的美国全市场
- 依赖：违反铁律 4
- 结论：等 L1/L2 的评估台跑通、且补上清盘基金 + 基金流数据之后再谈

## 4. 验收标准（沿用项目既有标准，不可放宽）

1. **必须跑过基线**：现有 6 因子 `quality_score` + 随机排序 + 等权。跑不过就如实报告负结果。
2. **严禁随机划分**训练/测试；必须 purged + embargo；标签重叠期不得进训练集。
3. **同窗口对比**：所有模型限制在同一 OOS 月份集合（`vol_model_comparison` 已立此规矩：旧版"基线跑全样本、ML 只跑 OOS"的对比不成立）。
4. **统计量三件套**：IC/ICIR + DM 检验 + 排列检验（并明确置换检验的零假设口径 —— 项目已有一次误读前科）。
5. **数据偏差披露**：幸存者偏差、`daily_return` 不可靠、无模拟数据（数据不足即过滤）。
6. **落地上限约束**：任何结论必须给出"扣费 + 扣换手后"的净额，而不是毛额。

## 5. 最小可行第一步（建议的执行清单）

```
1. src/analysis/recsys_dataset.py   面板构造：(t, fund) → 特征 + 下期标签
                                    复用 fund_scorer._load_nav_series / nav_series（acc_nav 口径）
2. src/analysis/recsys_ml.py        三模型：quality_score(基线) / rank_even / ridge(numpy)
                                    purged+embargo walk-forward 骨架（照抄 vol_predictor 的窗口逻辑）
3. tests/test_recsys_ml.py          防泄露测试：断言训练集不含标签重叠期；
                                    断言无未来函数（用 t 之后数据构造的特征必须为 NaN）
4. docs/recsys_ml_report.md         结论（含负结果）+ 与 quality_score 的对照表
```

**工期估计**：评估台 + 三模型 ≈ 一个批次；结论大概率是"线性模型略优于手工权重，但不足以改变排序结论"——**这个负结果本身就是交付价值**，它把"要不要做 ML 推荐"这个问题一次性钉死。

## 7. 诚实声明

- 本文引用的外部结论来自公开文献摘要（Kaniel et al. 2023 JFE；2025 年复现研究；DeMiguel et al. 的 GB/RF 结果）。**这些结论建立在美国全市场、含清盘基金的机构级数据上**，本项目的样本条件更差。
- 本文不含任何"ML 能提高收益"的承诺。按现有证据，**最可能的真实结果是"排雷有效、选优无效"**。
- 所有结论基于历史数据，不构成投资建议。
