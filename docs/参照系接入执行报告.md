### 0.2 我认为最可疑的数字：**A2 的「`fund_info.mgt_fee`（98.0% 填充）」**

任务书 §A2 要求把 `max_total_fee` 的口径改成「仅管理费」，并**按 `mgt_fee` 的实测分布重新定位阈值**，
括号里给的依据是「`fund_info.mgt_fee`（98.0% 填充）」。**实测这个 98.0% 是错的，而且错得很关键。**

```
=== 实测（python，真实库只读）===
fund_info 总数                       = 27,864
  mgt_fee          > 0 = 12,987  (46.6%)   ← 任务书说的 98.0%
  custodian_fee    > 0 =      0  ( 0.0%)   ← 与任务书一致（托管费恒为 0）
  fund_size        > 0 = 18,001  (64.6%)
  manager_tenure   > 0 = 18,675  (67.0%)
fund_profile_extra 行数              = 18,675
  fee_actual       > 0 =  9,469  (50.7%)
  peer_pct         > 0 = 18,309  (98.0%)   ← ★ 98.0% 其实属于 peer_pct，不是 mgt_fee
```

**mgt_fee 的真实分布，问题更大：**

```
有 mgt_fee = 12,987 只；min 0.01 / max 5.00
最常见取值：0.15(34.5%)  0.08(18.2%)  0.12(10.6%)  0.10(7.3%)  0.06(5.6%)  0.03(5.5%)
           0.80( 2.9%)  1.50( 1.3%)
若「仅管理费」用单一绝对阈值：
  >0.50 → 淘汰 882 只 (6.79%)      >0.80 → 319 只 (2.46%)
  >1.00 → 淘汰 254 只 (1.96%)      >1.20 → 194 只 (1.49%)
  >1.50 → 淘汰  17 只 (0.13%)      >2.00 →  10 只 (0.08%)
```

**结论（三条，全部可复现）**：

1. **98.0% 这个数是 `peer_pct` 的覆盖率，被误记到 `mgt_fee` 头上。** `mgt_fee` 只有 **46.6%**（`fee_actual` 50.7%）。
   按"实测分布"定位阈值，实际是在**不到一半的样本**上定，而另一半（53.4%）走 `⊘ 无数据` 直接跳过费率检查
   —— 这本身就是一条必须写进报告的数据缺失声明（铁律 5）。
2. **分布是双峰的**：0.15/0.08/0.12（货币、短债）与 0.80/1.50（权益）。**单一绝对阈值跨类型无意义**：
   阈值 ≤0.5 会把权益基金几乎全部淘汰（它们本来就在 1.2~1.5），阈值 ≥1.5 则形同虚设（只 0.13%）。
   这与任务书自己的 A1 原则冲突 —— A1 说"绝对概念保留绝对限值"，但费率上限**不是**绝对概念，
   它必须**按类型**（或组内分位）才能可比。**此处我建议偏离 A2 的"单一新阈值"做法**，理由如上。
3. **「该阈值永不触发」也是不准确的**：旧口径（mgt+cust）下 `total > 2.0` 实测**有 10 只**命中、
   `> 1.5` 有 17 只。准确说法是"近似失效（0.08%）"，不是"永不触发"。结论不变，但表述要改。

> 其余需要实测核验的数字（`momentum_warning` 失效程度、跨组 P81/P86/…、"常数是 P75 严格超集"）

### 0.3 追加实测（更严重）：**`mgt_fee` 这个字段本身就不可信，A2 的两条路都走不通**

按组统计后，分布形状就露馅了：

| 组 | n | 中位 | P75 | P90 | P99 |
|:--|--:|--:|--:|--:|--:|
| A 偏股混合 | 3,035 | **0.15** | 0.15 | 0.15 | 1.50 |
| B 灵活配置 | 1,402 | **0.15** | 0.15 | 0.15 | 1.50 |
| C 主动股票 | 620 | **0.15** | 0.15 | 0.15 | 0.88 |
| D 指数股票 | 1,914 | 0.12 | 0.12 | 0.15 | 1.20 |
| E 债券 | 4,802 | 0.08 | 0.08 | 0.56 | 0.80 |
| F QDII/其他 | 1,152 | 0.10 | 0.15 | 0.60 | 1.50 |

**偏股混合基金的管理费中位数不可能是 0.15%**（真实水平 1.2~1.5%）。抽样核对坐实了字段是坏的：

```
000021 华夏优势增长混合     (混合型-偏股)  mgt_fee = 0.15    ← 公开管理费 1.5%
000031 华夏复兴混合A        (混合型-偏股)  mgt_fee = 0.15
000970 东方红睿元混合       (混合型-灵活)  mgt_fee = 1.50    ← 同一个字段、同一个量级，却是对的
001286 易方达新鑫混合E                    mgt_fee = None
016371 信澳业绩驱动混合C（用户持仓）        mgt_fee = 0.0     ← 用户自己持有的 8 只全是 0/None
fund_profile_extra.fee_actual / fee_source  → 均为 0.0（应是费率来源字符串，明显错位）
```

**同一个字段里混着两套量纲**（0.15 与 1.5 并存），且**用户自己持仓的基金全部无费率数据**。
因此：

- **方案 B（单一绝对阈值）**：在坏数据上定阈值 —— 阈值 1.2% 时 A 组淘汰 4.1%、E 组 0.0%；
  阈值 1.5% 时几乎全组为 0（A 组 0.2%）。**不是"跨组不一致"，是"口径根本是错的"。**
- **方案 A（组内分位）**：虽然按组归一化后 6 组淘汰率都在 2.4%~10% 之间（比 B 均匀得多，见下图），
  但**分位是坏数据的分位**：A 组 P90 = 0.15% 意味着"管理费 >0.15% 就淘汰"，会把
  **华夏优势增长这类正常权益基金整片淘汰**（它们的真实管理费 1.5%）。**分位化救不了错数据，只会把错误均匀化。**

**结论（据此调整 A2 的做法，作为对任务书的偏离）**：
A2 的正确形态不是"换口径 + 定新阈值"，而是 **三件事**：
1. **先判定费率数据不可用**：`fund_info.mgt_fee` 量纲混用、`custodian_fee` 恒 0、`fee_actual` 错位 →
   在费率检查里**如实声明"费率数据不可用"**（铁律 5：不得用假值冒充），而不是拿 0.15 当阈值；
2. **口径改为「仅管理费」仍然要做**，但**只在数据可信的子集上**生效，并显式披露覆盖率（46.6%）；
3. **数据修好之前，不给费率设阈值**（或只保留"无数据"声明）—— 否则会做出一个看似合理、
   实则把正常基金淘汰掉（或全部放行）的检查。
   数据修复属于采集侧（对齐量纲），建议单独立项。

> 本节结论**推翻了任务书 A2 的可行性前提**（不只是"98.0% 写错了"，而是"这个字段现在不能用"）。
> 按任务书 §7.1 的要求，质疑必须用实测 —— 以上全部可复现：`scripts` 级脚本见 `D:\DSH\scratch_hold\cmp_fee_options.py`
> 与 `check_mgtfee_truth.py`（临时脚本，必要时可归入 `scripts/`）。

### 1.2 发现并修复一个**账本级 bug**（已实现收益漏计 ¥145.61）

结算后核对，发现 `#43` 的卖出**没有进入「已实现收益」**（笔数仍是 30）。追查后确认是系统性问题：

- **根因**：`reconcile()` 结算"下单时净值未公布"的买入时，**只回填持仓的 `shares`，
  没回填 `transactions.shares`**，留下 `0.0`；
  而 `get_realized_pnl()` 用 `sum(buy 流水的 shares)`，`shares <= 0 → continue` → **整只 lot 被跳过**。
- **影响面（实测）**：库里 **14 只 lot** 的买入流水 `shares=0`，其中 2 只已卖出 →
  **已实现毛额漏计 ¥145.61**（石油化工 ¥94.94 + 天弘电网 ¥50.67）；另外 12 只是"埋着的雷"，
  将来一旦卖出同样会静默消失。
- **修复**（三层，见 commit `fa8fbb8`）：
  1. **读路径**：买入流水 `shares<=0` 时按 SSOT 回退 `round(金额/确认净值, 2)` —— **不改写任何历史记录**（铁律 2）
  2. **写路径**：`reconcile()` 结算时一并回填 `transactions.shares`
  3. **护栏**：卖出成本 `min(按份额摊, 该 lot 总成本)` —— `#43` 曾因此被摊出 ¥50.84（> 实付 ¥50）造出 **−0.17 的假亏损**，实为 **+0.67**
- **复验**：已实现 30 → **32 笔**；毛额 1491.23 → **1636.84**（+145.61）；盈亏 −27.27 → **−33.08**；`#43 = +0.67`
- 新增回归测试 `tests/test_realized_pnl_legacy_buy.py`（5 例）；全测 **334 → 339 passed**

### 2.6 A2 费率口径 —— ⏸ **押后**（用户指示：先想清有没有更好的方案）

见 §0.2/§0.3 的实测：任务书的两条路（单一绝对阈值 / 组内分位）**都建立在不可信的
`mgt_fee` 上**。已记录的三个候选方向（待最后定夺）：
1. **如实声明"费率数据不可用"**，不设阈值（最保守，符合铁律 5）；
2. 口径改「仅管理费」+ **只在可信子集上生效并披露覆盖率**（46.6%）；
